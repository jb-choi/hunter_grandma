# 1. 플레이어에게 보이는 성장 경험

1. 처음에는 <b>샷건 할머니 1명</b>만 실제 화면에서 전투한다. 다른 할머니 슬롯은 <b>검은색 실루엣 + 자물쇠</b>로 노출한다.
2. 스테이지의 자동 사냥으로 성장 자원을 얻는 안을 검토한다(지급 규칙 D-04). 숙주형 보스 포획이 있는 회차는 제압·수레 귀환을 수행한다. Stage 01/02에 보스를 공통 필수로 넣지 않는다.
3. (미정)재화·추가 재료(도입 여부 미정)를 모아 현재 할머니의 스탯과 무기를 강화한다.
4. 조건을 충족하면 잠겨 있던 다음 할머니가 <b>실루엣에서 컬러 캐릭터로 바뀌는 연출</b>과 함께 합류한다.
5. 새 할머니가 가져오는 <b>새 공격 방식 또는 운송 기능</b>이 화면에 추가되어 이전보다 강하고 화려한 전투단이 된다.
6. 해금한 할머니와 무기를 키워 다음 지역을 돌파한다. 현재 선택 지역에서는 V/CLEAR 후 자동 재사냥한다. 보스 포획은 포획 콘텐츠의 반복 보상, 고유 동료 구출은 최초 1회 사건으로 구분한다.

<b>차별화할 핵심:</b> 수치가 오르는 것뿐 아니라 <b>검은 캐릭터 카드가 컬러로 열리고 실제 전투 화면에 새로운 할머니가 나타나는 순간</b>을 큰 성장 보상으로 만든다.

<b>하이브리드 결합:</b> 정지/걷기/줍기는 원본 통그림, 이동 중 Aim/Fire/Reload는 무기 없는 Walk 몸체 + 해당 상체를 별도 SpriteRenderer로 합성한다. 원본 시연과 같은 머리/어깨 정렬을 적용했다. 120×120 캔버스·바닥 피벗·표시 크기를 맞추고 좌우 총구도 반사한다. 원본 프레임 시간을 보관하되 사격/장전은 기존 강화에 따른 발사 간격에 맞춘다.

<b>구현 단위:</b> <code>SundeokAnimationSet</code>의 C# 재생 데이터 6클립이며 Unity Animator/<code>.anim</code> 6개를 만든 것은 아니다. 게임용 PNG 81개 = Composite/Body/Upper 각 27개 출력·복사본으로, 신규 작화 81장으로 집계하지 않는다. 원본 native/PNG/메타데이터 45개 SHA-256 유지. 일반 저장·ProjectSettings·Build Settings·manifest도 작업 시작 시점 해시와 일치한다.

<b>게임 규칙:</b> 실제 이동/사거리/피해/보상/저장은 기존 조우 코드가 소유한다. Collect는 이미 지급한 보상을 다시 주지 않는다. 새 탄약 수·장전 대기 경제는 추가하지 않았다. 일시정지/도입/hit stop은 동작 시간도 멈추며 재도전은 상태를 초기화한다. Stage 0의 64px 차 마시는 도입은 유지한다.

<b>실행 검증:</b> Unity 6000.3.10f1 Editor에서 전용 애니메이션 <b>45</b>, 기존 전투·포획·저장 <b>156</b>, Stage 0 도입/좀비 공격 <b>48</b>, 강화 UI <b>103</b> — 합계 <b>352개 PASS</b>, 각 suite 런타임 오류/예외/assertion 0건. 별도 Library 프로필 사용. 27장 재합성 픽셀 일치·12개 원본 시연 정렬값·6동작/이동 사격/좌우 총구/정지/줍기 보상 1회/재도전을 확인했다. 플레이어 빌드·장시간 성능 검사는 미실행.

<b>로컬 증빙:</b> <code>Docs/Sundeok120-Animation-Integration.md</code>, <code>Docs/Validation/Sundeok120-animation-validation.md</code>, <code>Sundeok120-preservation.json</code>, <code>Sundeok120-walk-fire.png</code>(Docs/Validation 기준). 첫 검사 fixture의 프레임 경계 실패 기록은 보존하고 실제 키보드 이동으로 수정·재실행했다. 화면/UI 연결 기록은 <mention url="https://app.notion.com/p/4067313398e081b5b0d1fe284d521bc3" /> 8.2 E11을 따른다.

# 3. 파워 그릇(Power Container) — 무엇이 강해지는가?

| 그릇 | 저장하는 성장치 | 실제 플레이에 반영되는 예 | 초안의 소유 단위 |
| --- | --- | --- | --- |
| <b>개별 할머니</b> | 레벨·개인 스탯·특성 | 명중, 생존, 제압 숙련, 지원 효율 | 할머니 ID별 영구 |
| <b>개별 무기</b> | 무기 레벨·무기 성능 | 데미지, 연사력, 공격 범위, 사거리 | 무기 ID별 영구 |
| <b>운송 장비/수레</b> | 적재 능력·운반 효율 | 포획 개체 운송 효율 | 수레 ID별 영구 |
| <b>전투단 공통 성장</b> | 전체 적용 영구 보너스 | 전체 공격·제압·운송 효율 | 도입 여부 미결정 |

<b>설계 원칙:</b> 할머니 레벨과 무기 레벨을 하나로 합치지 않는다. 할머니는 <b>누가 얼마나 숙련됐는지</b>, 무기는 <b>무엇을 들고 얼마나 강력하게 공격하는지</b>를 담당한다. 무기 성능과 할머니 개인 스탯이 최종 전투 성능에서 합쳐진다.

<b>확정된 장비 운용 범위:</b> 01\~04는 각각 샷건·화염방사기·기관총·저격총만 사용한다. 무기 교체·교차 장착·장비 세트는 현재 기획 범위에 넣지 않는다. 전용 무기의 강화·외형 단계는 별도로 발전시킬 수 있고 캐릭터·무기 스탯은 분리한다. 05의 담당 역할은 D-03 미정.

# 4. 스탯 구조 — 할머니 강화 vs 무기 강화 (모두 초안)

## 4.1 할머니 스탯

| 스탯 후보 | 의미 | 플레이 체감 |
| --- | --- | --- |
| 숙련도 | 자신의 무기를 더 효율적으로 사용 | 같은 총을 들고도 더 빠르고 정확하게 공격 |
| 공격 숙련 | 캐릭터 자체의 공격 기여 | 기본 피해 보정 |
| 생존력 | 피격 버티기 | 출정 실패율 감소 |
| 제압 숙련 | 숙주형 보스 무력화 지원 | 보스 제압까지 걸리는 시간 감소 |
| 운송 숙련(운송 할매 중심) | 적재·귀환 능력 | 회수 처리 시간이 짧아짐 |

처음부터 5개를 전부 UI에 띄우지 말 것. <b>대표 레벨 1개 + 역할별 핵심 스탯 1\~2개</b>로 시작하고, 세부 원천값은 내부 데이터로 관리하는 안 검토.

## 4.2 무기 스탯

| 무기 | 강화 후보 | 뚜렷한 시각 효과 |
| --- | --- | --- |
| 샷건 | 공격력·발사 간격·산탄 폭 | 한 발에 더 많은 좀비가 밀려남 |
| 화염방사기 | 지속 피해·범위·유지 시간 | 불길이 길고 넓게 유지됨 |
| 기관총 | 연사·탄량·관통 | 끊기지 않는 탄막 |
| 저격총 | 단발 피해·사거리·관통 | 큰 적에게 강한 단발 피격 |
| 수레 | 운반속도·적재능력 | 수레 동작과 적재 모습 변화 |

<b>중복 주의:</b> 개인 공격력과 무기 공격력을 모두 성장시키되, 둘이 완전히 같은 버튼이라면 의미가 없음. 비용·성장 곡선·해금 시점·시각적 체감 중 적어도 하나가 달라야 한다.

# 5. 재화 → 업그레이드 → 전투력 연결

| 자원 종류 | 획득처(안) | 소비·사용처(안) | 역할 |
| --- | --- | --- | --- |
| <b>(미정)재화</b> | 획득처 미정(현행 프로토타입은 일반 좀비 사살·스테이지 보상) | 소비처·비용 미정(기본 강화 재화로 쓰는 안) | 재화 명칭·유형·수량 체계 확정 전 UI 자리표시자 |
| <b>(미정)추가 재료</b> | 추가 자원 도입 여부 및 획득처 미정 | 승급·구간 돌파 등에 쓰는 안(미정) | 별도 재화를 반드시 도입한다는 뜻 아님 |
| <b>누적 포획 기록</b> | 스테이지 반복 클리어·숙주형 보스 포획 | 할머니 해금 또는 달성 조건(소비 아님) | 장기 목표·전진 동기 |

- <b>재화 수 확정 아님.</b> 출시 초기에 같은 역할의 재화를 여러 종류로 복제하지 않는다.
- '해금 조건 충족'과 '해금 비용 지불'은 구분해야 한다. 포획 횟수를 기록하는 것과 포획한 사람을 소비해 동료를 구매하는 것은 전혀 다른 경험이다.
- <b>기존 전투 보상안과의 관계:</b> 기존 프로토타입은 일반 좀비 처치·용해 후 '골드'를 지급하지만, 최종 재화 명칭·획득처·소비처는 <b>(미정)</b>. 숙주형 보스는 제압·포획하며 포획 대상을 재료나 희생 비용처럼 쓰지 않는 방향을 권장.

## 5.1 성장 연산의 구분

1. <b>반복 강화:</b> (미정)재화 소비(예시) → 샷건 피해량 +n, 기관총 발사 간격 감소 등.
2. <b>단계 승급:</b> 특정 재료와 조건 충족 → 무기 등급 한 단계 상승, 신규 효과/외형 변화.
3. <b>캐릭터 해금:</b> 잠긴 할머니 카드 → 컬러 전환 + 출전·지원 기능 활성화.
4. <b>영구 기록:</b> 스테이지 최초 클리어, 보스 포획 누적 등. 캐릭터 해금 조건/마일스톤으로 활용 가능.

## 5.2 선행 구현 스킬 — 순덕 「할매의 밤마실」

<date start="2026-10-29" />

<callout icon="🌙" color="purple_bg">
<b>업그레이드 체계는 아직 미정이며, 스킬 1개를 먼저 구현한 상태다.</b>

할머니·무기·스킬의 전체 강화 구조, 해금 조건, 비용과 성장 곡선은 확정하지 않았다. 그에 앞서 순덕의 고유 스킬 <b>「할매의 밤마실」</b>을 실제 게임에서 사용할 수 있도록 구현하고 연출·자동 발동을 검증했다. 이 기록은 전체 성장 시스템의 완성을 뜻하지 않는다.
</callout>

### 플레이어가 보는 동작

1. 전투 시간이 잠깐 멈추고 배경이 어두워진다.
2. 순덕 할매가 검은 연기 속으로 사라졌다가 앞에 있는 좀비의 뒤통수 쪽에 나타나 <b>탕!</b> 쏜다.
3. 다른 좀비 뒤에 다시 나타나 사격한다. 서로 다른 표적을 우선하며 <b>총 5회</b> 반복한다.
4. 마지막 발은 조금 더 강한 총성과 긴 반동으로 마무리하고, 처음 위치·방향으로 복귀한다. 암전이 풀리고 전투가 이어진다.

### 현재 구현된 사용 규칙

| 항목 | 현재 시제품 동작 |
| --- | --- |
| 사용 캐릭터 | 순덕 할매 1명 |
| 설정 위치 | <b>U → 순덕 할매 상세 → 「할매의 밤마실」 ON/OFF</b>. 상세 목록 첫 카드에 배치 |
| 기본값·저장 | 기본 <b>OFF</b>. ON/OFF 선택을 기존 플레이어 저장에 보관 |
| 자동 발동 | ON 후 <b>전투 시간 10초마다</b> 자동 사용. 시전이 끝나면 다시 전투 시간 10초를 센다 |
| 시간 계산 | 전투 진행 시간을 기준으로 함. 일시정지·지도·도입·비전투 구간·스킬 연출 중에는 대기시간이 진행되지 않음 |
| 표적 | 화면 안에서 순덕이 바라보는 전방의 살아 있는 <b>일반 좀비</b>. 뒤에 나타날 공간이 있어야 하며 보스는 현재 대상에서 제외 |
| 표적 수가 적을 때 | 다른 좀비부터 한 번씩 공격한 뒤 살아 있는 표적을 다시 공격해 5발을 채움. 모두 쓰러졌다면 일찍 복귀 |
| 표적이 없을 때 | 발동 준비 상태로 기다렸다가 조건을 만족하는 좀비가 생기면 사용 |
| 현재 피해량 | <b>발당 현재 공격력 ×2</b>. 기존 처치·보상 처리를 사용하며 중복 보상 없음 |
| 시간 정지·보호 | 적 이동·공격, 일반 탄환, 자동 사격·이동과 카메라 진행을 멈춤. 사라진 본체는 스킬 중 피격되지 않음 |
| 중단·재개 | 사용자 일시정지·지도에서는 연출도 정지. OFF·재도전·후퇴·지역 이동 시 효과를 정리하고 정상 상태로 복구 |
| UI 표시 | ON/OFF, 다음 발동까지 남은 시간, 연속 사격 진행 횟수 표시 |

<b>현재 수치의 의미:</b> 10초 자동 발동·5연사·공격력 ×2는 이번 시제품의 실제 구현값이다. 현재 ON/OFF에는 별도 재화 비용이 없다. 이를 스킬 획득 조건이나 최종 강화 비용·밸런스의 확정안으로 확대하지 않는다.

### 아직 정하지 않은 업그레이드 항목

- 스킬을 언제·어떤 조건으로 획득/해금하는지.
- 스킬 레벨·강화 단계의 유무, 강화 비용과 사용 재화.
- 피해량·재사용 대기시간 등 무엇을 성장시킬지와 구체 계산식.
- 할머니 개인 성장·전용 무기 성장·스킬 성장 사이의 연결 방식.
- 다른 할머니들의 고유 스킬 및 여러 할머니가 함께 사용할 때의 처리.

<b>구현·검증 기록:</b> Unity 6000.3.10f1 Editor에서 스킬 전용 <b>33개 검사 PASS</b>. 기존 업그레이드 UI 103·전투/스테이지 156·순덕 애니메이션 45·도입/좀비 공격 48을 함께 재검증해 <b>총 385개 PASS</b>, 각 검사에서 런타임 오류·예외·assertion 0건. ON/OFF 저장, 10초 반복, 5연사, 지도/일시정지, 전멸 시 조기 복귀, 중단 시 복구를 확인했다. 플레이어 빌드·장시간 성능 검사는 미실행이다.

# 6. 동료 해금의 상태 계약

| 상태 | 성장 시스템의 의미 | UI가 전달할 정보 |
| --- | --- | --- |
| 잠김 | 소유·출전 기능 미활성 | 검은 실루엣·자물쇠·(미정)해금 조건 |
| 해금 가능 | 요건 충족. 비용·입력 방식 미정 | 조건 충족 상태와 가능한 행동 |
| 해금됨 | 캐릭터 영구 해금 기록 | 컬러 카드·역할·성장 진입점 |
| 전투/지원 참여 | 해금된 동료를 필드에 배치 | 실제 등장·고유 공격/지원 행동 |

- <b>구출 ≠ 해금 ≠ 출전:</b> Stage 02 사건은 03에서 관리한다. 즉시 해금·자동 출전·운송 역할은 D-03·D-05로 결정한다.
- <b>조건과 비용:</b> 누적 포획 수 같은 달성 기록과 소비 자원을 구분한다. 조건 달성만으로 기록을 차감하지 않는다.
- <b>최초 1회:</b> 고유 동료 구조·해금 상태는 반복 회차 후에도 유지하고 중복 획득을 막는다.
- <b>비주얼 훅:</b> 무기 실루엣→컬러 공개→고유 동작→필드 합류를 성장 보상으로 만든다. 잠금 아트는 완성 스프라이트의 어두운 마스킹을 우선 검토한다. <b>120×120 시험 아트</b>에서 발 위치 Y 정렬·캐릭터 겹침을 검증하되, 기존 64×64 구현과 혼동하지 않는다.
- 카드 배치·버튼·연출 에셋은 <mention url="https://app.notion.com/p/4067313398e081b5b0d1fe284d521bc3" />에서 관리한다. 샷건/화방/기관총/저격/운송 순서는 레이아웃 예시이며 해금 순서가 아니다. 해금 버튼·자동 해금 방식은 미정이며 랜덤 뽑기·과금을 전제로 하지 않는다.

# 7. 스테이지 돌파에 연결하는 예시 (제안 흐름)

```txt
Stage 1 반복
  → 일반 좀비 사살: (미정)재화 획득(예시; 지급 규칙 미확정)
  → 숙주형 보스 제압·포획: 클리어 및 누적 포획 기록
  → 샷건 할매 스탯·샷건 강화
  → 특정 진척/조건 달성: 화방 할매 해금
  → 검은 실루엣 → 컬러 캐릭터 + 벨트스크롤 전투 합류
  → 광역 화력 증가 / 다음 Stage 돌파
  → 이후 기관총·저격·운송 할매 등 차례로 합류
```

<b>예시의 범위:</b> 위 흐름은 기존 보스 포획 콘텐츠에서 성장시키는 예시다. 화방 할매의 첫 해금, Stage 01/02의 보스 유무·해금 순서를 확정하지 않는다. Stage 02 구출 이후 성장·합류 연결은 D-03으로 결정한다.

# 8. 밸런스·개발 제약

- <b>화면 복잡도:</b> 동료가 5명 모두 동시에 출전하면 적·탄막·화염·수레가 겹쳐 가독성이 깨질 수 있다. <b>120×120 시험 제작</b>과 실제 게임 화면 출력 배율에서 밀집도·겹침을 검증하고, 최대 동시 출전 인원은 테스트로 결정.
- <b>방치형 적합성:</b> 플레이어가 모든 할머니에게 목표 지정·재장전·포지션 명령을 내리는 게임으로 변하지 않게 한다. 자동 사냥은 기본 방향이다. 자동 운송·역할 협력·수동 개입 상세는 D-05로 검토.
- <b>벨트스크롤 이동:</b> X/Y 좌표와 발 위치 기반 정렬, 역할별 사거리·깊이(Y) 차이 명중 판정 테스트.
- <b>성장 폭주:</b> 할머니 5명 레벨과 무기 5개 레벨이 독립적으로 늘어나면 강화 화면이 과밀해질 수 있다. '할머니 카드 안에서 해당 무기 강화'로 묶되 성장값은 분리하는 방식 추천.
- <b>수치와 영상의 일치:</b> 공격력 +5%로 체감이 미미한 구간보다 '한 발에 녹이는 적 수 증가', '합류 인원 증가', '수레 실루엣 변화'처럼 눈에 보이는 전환점을 우선 검증.
