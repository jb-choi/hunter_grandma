# walk_retry 제작에 주요하게 작용한 요소

2026-10-13 · Hunter64/v001 · HU-02 걷기 재시도

대상은 [walk_retry.aseprite](walk_retry.aseprite)다. 이번 작업은 사용자가 수정한 디자인으로 **빈 프레임이 없는 연속 걷기**를 만드는 별도 시도였다. 기존 `walk.aseprite`와 `walk_another.aseprite`는 보존했다.

결과에 크게 작용한 것은 **최신 원본의 실제 픽셀 확인, 부위별 분할과 접점 규칙, 걷기 단계의 연결, 전신 검수 후 국소 보정**이었다. 자연어 지시를 실제 수정으로 옮기기 위해 기준 파일·마스크·좌표·검수 기록을 함께 사용했다.

## 1. 사용자 요구와 작업 기준

| 요소 | 이번 작업에 적용한 내용 | 작용한 이유 |
|---|---|---|
| 캐릭터 인상 보존 | 머리·모자·깃털·머리카락·얼굴·눈과 기존 의상·장비 디자인을 기준으로 사용 | 동작을 만들면서 캐릭터가 다른 그림으로 바뀌는 것을 방지했다. |
| 기존 픽셀 직접 수정 | 이미지 재생성·블러·안티앨리어싱·디더링 없이 Aseprite의 Indexed 픽셀을 복사·이동·재작화 | 색 조각이나 흐린 경계를 새로 만들지 않고 수정 범위를 통제했다. |
| 현재 색과 해상도 유지 | 64×64, 팔레트 17칸 유지. 투명 인덱스는0이며 나머지는 기존 색 | 캔버스·색을 고정한 상태에서 포즈와 연결에 집중했다. 17칸은 실제 사용 색 수와 같은 의미가 아니다. |
| 새 파일로 재시도 | 같은 HU-02 폴더의 `walk_retry.aseprite`에 저장 | 기존 키포즈·수동 수정본을 계속 비교하고 되돌아볼 수 있다. |
| 원본·출력·검수 분리 | 보존본은 Source, PNG는 Frames, 시트/명세는 Export, 마스크는 Masks, 판단 근거는 QA | 편집 원본과 재생성 가능한 출력, 비교용 안내가 섞이지 않게 했다. |

저장과 검수에는 [ArtSource 작업 지침](../../../../../AGENTS.md), [제작 가이드](../../../../../../Docs/AI/Art/02_Production/ProductionGuide.md), [픽셀 정리 가이드](../../../../../../Docs/AI/Art/02_Production/PixelCleanupGuide.md)의 기준을 참고했다. 실제 작업 범위와 보존 요구는 사용자의 요청을 기준으로 정했다.

## 2. 최신 원본을 정확히 선택한 것

직접 사용한 기준은 [보존된 walk_another.aseprite의 F1](Source/WalkRetry/p001/walk_another.aseprite)이다. `idle_breath`와 기존 `walk`도 함께 비교했다.

- `walk_another` F1의 머리·상의·팔·새총·자루는 idle F1과 같았다.
- LowerBody에는 **43픽셀 차이**가 있었다. 옷자락은 변경0, 바짓단7점, 부츠36점이었다. 이 값은 변경 좌표 수이며 최종 불투명 픽셀 수가 아니다.
- 최신 부츠 템플릿은 뒤31px·앞42px, 합계73px이었다.
- 앞부츠에 **x31의 5픽셀**이 있으므로 옛 `front x≥32` 분할을 그대로 쓰면 원본 일부가 빠진다. 이번에는 y51~56에서 `rear x≤30 / front x≥31`로 나눴다.
- 사용자 F2/F3의 좁아진 몸과 기울어진 새총은 수동 포즈 시험으로 참고했다. 이를 모든 프레임의 공통 디자인으로 복사하지 않았다.

이 입력 비교가 최신 부츠 디자인을 보존하고, 분할 경계 때문에 생길 수 있는 누락을 막는 데 직접 작용했다. 근거는 [입력 비교 기록](../../QA/WalkRetry/p001/Review/source_review.md)과 [하체 전후·차이 이미지](../../QA/WalkRetry/p001/Review/lower_f01_before_after_diff_8x.png)에 있다.

## 3. 부위 분할과 움직임의 기준점

작업 중에는 몸통·양팔·양다리·부츠·자락·새총·자루를 임시로 구분했다. 최종 파일에는 원본의 6개 레이어 이름과 순서를 유지했다.

| 최종 레이어 | 표시 | 역할 |
|---|---|---|
| backgroud_temp | 숨김 | 기존 임시 배경 보존, 캐릭터 출력 제외 |
| Bow&Quiver | 숨김 | 이전 장비 보존, 캐릭터 출력 제외 |
| Slingshot&bag | 표시 | 새총과 자루의 서로 다른 이동을 합쳐 저장 |
| LowerBody | 표시 | 옷자락·골반·무릎·양다리·부츠 |
| UpperBody_Arms_Equipment | 표시 | 복원한 상의 면과 움직이는 양팔·손 |
| Head_Hat_Hair_Face | 표시 | 머리 전체의 형태를 유지한 높이 변화 |

**팔 뒤의 상의 면 복원**이 특히 중요했다. 원본에서 팔이 가린 영역을 빈 채로 두고 팔만 이동하면 네모난 투명 구멍이 드러난다. 양쪽 상의·벨트의 숨은 면을 기존 색으로 먼저 채운 다음 팔을 움직였다.

손·소매는 원래 픽셀을 사용하고 어깨에서 손목으로 갈수록 이동량이 커지도록 정수 행 단위로 변형했다. 머리는 얼굴만 따로 움직이지 않고 통째로 정수 이동했다. 새총은 앞손 그립을 따르고, 자루는 몸 높이와 작은 지연 움직임을 따르게 했다.

[부위 마스크](Masks/WalkRetry/material_regions.aseprite)는 캐릭터 부분과 다리·팔·자락의 가림을 확인하는 데 사용했다. 마스크의 안내 색과 레이어는 캐릭터 PNG/GIF에 포함하지 않았다. 이 좌표 분할은 이번 원본에 맞춘 것이므로 디자인이 바뀌면 다시 확인해야 한다.

## 4. 걷기 사이클을 구성한 규칙

기존 walk의 빈 F2·4·6·8은 키포즈 검토를 위해 남겨둔 상태였다. 이번 연속 재시도에서는 반복 구간의 모든 프레임을 그렸다.

| 프레임 | 걷기 단계 | 주요 변화 |
|---|---|---|
| 1 | 앞발 착지 | 최신 사용자 첫 자세 그대로 |
| 2 | 몸 낮춤 | 뒤발을 들어 올리며 다음 교차 준비 |
| 3 | 뒤발 통과 | 뒤무릎을 굽히고 부츠를 들어 올림 |
| 4 | 몸 상승 | 뒤발을 전방으로 뻗어 반대 착지 준비 |
| 5 | 반대발 착지 | 앞뒤 발의 역할 교대 |
| 6 | 몸 낮춤 | 앞발을 들어 올리며 다음 교차 준비 |
| 7 | 앞발 통과 | 앞무릎을 굽히고 부츠를 들어 올림 |
| 8 | 몸 상승 | 앞발을 전방으로 뻗어 첫 자세로 연결 |
| 9 | 닫힘 참조 | F1 셀 이미지·좌표의 정확한 복사본 |

- `walk` 태그는 F1~8, 각120ms, 총960ms 반복이다.
- F9는 `cycle_close` 태그의 별도 참조다. 반복에 함께 넣어 첫 자세가 두 번 머무는 것을 피했다.
- 몸·머리의 높이는 `0, +1, 0, -1`을 두 번 반복했다. 양수 y는 하향이다.
- 팔은 다리와 반대 방향으로 최대±2px 움직였다. 앞손·새총에는 필요한 구간에 추가1px 하향을 넣어 얼굴과의 접촉을 피했다.
- 자루는 몸의 높이를 따르면서 좌우±1px 지연을 넣었다.
- 골반→무릎→커프를 연결하고, 올라온 다리 위의 자락 끝만1px 올렸다. 중앙 자락 패임은 몸의 높이 변화를 제외하고 유지했다.

좌표는 **캔버스 좌상단 원점·0부터 시작하는 픽셀 값**이다. 세부 이동값은 [motion.json](../../QA/WalkRetry/p001/motion.json)에 기록했다.

## 5. 검수에서 실제로 바뀐 중요한 부분

초안의 F3 뒤발과 F7 앞발은 원본에서2px 들어 올린 상태였다. 교차하면서 앞뒤 부츠가 많이 겹쳐 작은 표시 크기에서 한 발처럼 읽히기 쉬웠다.

수정본은 해당 발을 **3px 들어 올리고 커프·자락 연결을 함께 맞췄다.** 지지 발의 밑창은 y56, 들린 발은 y53이다.

| 확인값 | 초안 → 수정본 | 의미 |
|---|---|---|
| F3 부츠 템플릿 겹침 | 18 → 14px | 뒤발의 독립 노출이9 → 13px로 증가 |
| F7 부츠 템플릿 겹침 | 17 → 14px | 지지 뒤발의 독립 노출이14 → 17px로 증가 |

발의 일부 겹침은 남아 있다. 가까운 다리와 자락이 먼 부츠를 가리는 깊이 표현이므로, 보이는 픽셀 수가 줄었다고 원본 부츠 삭제로 판단하지 않았다. 완전히 분리된 양발 실루엣이라고도 판정하지 않았다.

이 보정은 색 수 검사만으로 찾기 어려웠고, **64px 전신 확인과 밝은 배경의 교차 발 확대 검수**가 결정에 작용했다. [작화 판정](../../QA/WalkRetry/p001/Review/visual_review.md)과 [교차 발16배](../../QA/WalkRetry/p001/Review/retry_crossing_feet_16x.png)에 근거를 남겼다.

## 6. 제작 도구와 검수 방식

실제 편집은 Aseprite CLI와 Lua로 수행했다. Aseprite 정보 도구로 구조를 확인하고, Lua에서 source 셀·팔레트·좌표를 읽어 기존 Indexed 픽셀을 직접 조작했다. 이 방식으로 색인값과 셀 좌표, 원본에서 이동한 부분과 새로 그린 연결부를 명시적으로 관리했다.

| 검수 | 확인한 범위 | 근거 |
|---|---|---|
| 저장 파일 검수 | native를 다시 열어 PNG·시트·GIF·확대 GIF·마스크 일치, 팔레트·태그·시간·알파·머리/장비 이동·보이는 부츠 색·그립 확인 | [native_validation.json](../../QA/WalkRetry/p001/native_validation.json) |
| 기준 자세 보존 | F1/F9 셀 이미지·좌표의 원본 대비 변경0 | 같은 native 검사 |
| 독립 작화 검수 | 전9F의 머리부터 신발·장비까지64px/8배, 교차 발16배. 상의 구멍·접점 단절·눈 훼손·가림 구분 | [Review/visual_review.md](../../QA/WalkRetry/p001/Review/visual_review.md) |
| 재생기 검수 | 작화8F 로드/선택, 반복2회, F9 제외·별도 참조,64px/800% Point, 배경 전환,390px 화면, 링크7개·오류0 | [browser_validation.json](../../QA/WalkRetry/p001/browser_validation.json) |
| 원본 보존 | 기존 native10파일의 해시 유지 | [source_hash.json](../../QA/WalkRetry/p001/source_hash.json) |

수치 일치와 작화 판단은 별도로 확인했다. 이번 결과는 **별도 걷기 시험본**이며 Unity 적용이나 실제 게임 화면 검수를 수행한 것은 아니다.

다음 수정에서도 먼저 기준 프레임과 부위 분할을 확정하고, 손·장비·무릎·발 접점을 규칙으로 기록한 뒤, 전 프레임의 실제 표시 크기와 반복 재생을 함께 확인하는 것이 주요 작업 순서다.
