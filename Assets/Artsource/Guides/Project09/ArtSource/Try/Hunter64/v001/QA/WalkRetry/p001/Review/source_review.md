## F1 디자인 변경 해석

walk_another F1과 F5는 같은 기준 자세다. 머리 전체·상의·팔·새총·자루·숨긴 옛 활은 idle F1과 동일하며, LowerBody만 43픽셀 차이가 있다. 하체 불투명 픽셀은 191→184다. 이는 옷자락이나 몸통 변경이 아니라 양쪽 부츠와 바짓단의 새 디자인이다.

[하체 원본 / 사용자 수정 / 차이 8배](lower_f01_before_after_diff_8x.png). 차이 패널은 빨강=삭제, 청록=추가, 노랑=색 변경이며 회색은 기존 형태다.

| 영역 | 기존 / 사용자 불투명 픽셀 | 변경점 | 해석 |
|---|---:|---:|---|
| 자락 y43..48 | 88 / 88 | 0 | 새총·자루 뒤 옷자락, 중앙 패임과 명암은 그대로다. |
| 바지 y49..50 | 24 / 23 | 7 | y50의 다리 끝 외곽과 녹색 명암을 부츠의 새 폭·위치에 맞춰 정리했다. |
| 부츠 y51..56 | 79 / 73 | 36 | 뒷부츠 오른쪽 외곽이 좁아지고 발끝 금색이 x28에서 x27로 옮겨졌다. 앞부츠는 왼쪽 x31까지 넓어지는 대신 오른쪽 x39가 삭제되어 전체적으로 왼쪽으로 1px 옮긴 형태다. |

43점은 삭제 14, 추가 7, 색 변경 22점이다. 두 발바닥은 y56으로 유지된다. 새 retry가 최신 사용자 발 디자인을 따르려면 idle/옛 walk 부츠를 재사용하지 말고 walk_another F1의 부츠 픽셀을 기준으로 해야 한다.

**중요한 분할 경계:** 사용자 앞부츠에는 x31의 y51·52·54·55·56 다섯 점이 새로 있다. 옛 `rear x≤30 / front x≥32` 부츠 분할은 이 다섯 점을 떨어뜨린다. 새 부츠 분할은 y51 이후에서 `rear x≤30 / front x≥31`을 사용한다. 이때 뒷부츠와 앞부츠는 원본 그대로 별도 이동시킬 수 있다. 허벅지·무릎·바짓단 연결은 이동한 부츠의 실제 커프에 맞춰 다시 그린다.

walk_another 1~5는 옛 walk 1·3·5·7·9의 순서와 대응한다. 머리 전체와 숨긴 Bow&Quiver는 대응 프레임과 전부 동일하다. 변경된 새 장비와 몸·다리만 따로 해석한다.

픽셀 수나 발의 겹침만으로 사용자 수정이 잘못됐다고 판정하지 않는다. F2/F3는 포즈 시험 중의 손·새총·다리 변형이다. 다만 native 64px에서 어느 발이 지지하고 어느 발이 올라가는지 분리해서 읽기 어려우므로, 새 연속 보행에서는 앞뒤 부츠 겹침과 들린 뒤꿈치·무릎의 구분을 별도로 검수한다.

## 새 retry에 재사용할 기준과 주의점

- 사용자 F1의 몸·머리·장비는 현재 idle F1과 같으므로 기존 70픽셀 rear-arm, 57픽셀 front-arm 분할과 양쪽 숨은 셔츠 면 복원을 재사용할 수 있다. 움직이는 팔을 그대로 잘라 옮겨서 셔츠에 사각 구멍을 만들지 않는다.
- 부츠 디자인은 사용자 F1을 재사용하고, 사용자 F2/F3의 좁은 몸이나 새총 기울기를 자동 전 프레임 기준으로 적용하지 않는다. 단일 반복 보행에서 몸통의 폭과 장비 인상이 흔들리지 않아야 한다.
- 팔과 손의 움직임에 새총 그립을 붙이고, 자루는 몸 높이와 작은 지연을 따른다. 머리 전체는 source 형태를 그대로 정수 이동한다.
- 기존 walk의 가장 명확한 재생 결점은 F2·4·6·8이 빈 프레임이라는 점이다. 9개 프레임으로 반복하면 캐릭터가 계속 사라져 동작 연결을 확인하기 어렵다. 새 retry는 8개의 비어 있지 않은 연속 포즈를 만들고, 필요하면 F9에 F1을 동일 복사한 닫힘 참고를 별도 태그로 둔다.
- 기존 비교 F10·11은 구부린 무릎과 자락 변형의 참고 이력이다. 이번 독립 source 검수에서 새 retry 완료나 재생 통과를 선언하지 않는다. 기존 원본의 native 격리 표시 상태·배경 레이어는 변경하지 않으며, 비교 PNG만 임시로 몸·새 장비 표시/옛 활·배경 숨김 정책을 적용했다.

입력 3파일의 전신·후속 사용자 포즈는 64px와 8배에서 실제 열어 확인했다. 기존 9프레임의 의도된 빈 프레임과 새 사용자 부츠 디자인을 구분했으며, 이 검수에 따른 기존 native 수정은 없다.
