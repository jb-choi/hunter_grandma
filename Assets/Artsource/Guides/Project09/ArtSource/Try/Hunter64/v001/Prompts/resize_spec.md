# Hunter64 v001 — idle 축소 명세

2026-10-11 · 사용 요청: Hunter_300의 idle만 Hunter64로 옮겨 비교한다.

## 입력과 출력

- 입력: `Hunter_300/v006/Clips/HU-01_idle/idle.aseprite`, 300×300 Indexed.
- 보존본: [idle_300_v006.aseprite](../Clips/HU-01_idle/Source/idle_300_v006.aseprite).
- 출력: [idle.aseprite](../Clips/HU-01_idle/idle.aseprite), 64×64 Indexed.
- 유지: 2프레임, 각 500ms, 정방향 `idle` 태그, 원본의 17칸 팔레트와 투명 인덱스 0.

## 변환 방법

출력 `(x, y)`의 소스 좌표는 다음과 같다.

```text
source_x = floor((x + 0.5) * 300 / 64)
source_y = floor((y + 0.5) * 300 / 64)
```

선택한 원본 팔레트 인덱스 하나를 그대로 출력한다. 두 프레임에 같은 전체 캔버스 좌표 변환을 적용하며 프레임별 crop·trim·재배치를 하지 않는다. 부위 마스크 역시 같은 좌표 변환을 사용한다.

캐릭터 디자인·포즈·표정·장비 방향을 유지한다. 이번 시험은 해상도 비교를 위한 축소본이며 추가 재작화나 새 포즈 생성을 지시하지 않는다. 이미지 재생성, 색 평균 보간, 블러, 안티앨리어싱, 디더링을 사용하지 않는다. 확대 미리보기도 최근접 보간을 사용한다.

[실제 변환 기록](../QA/conversion.json)의 추가 픽셀 수정은 0개다. 눈의 샘플 결과는 1번 1×2px, 2번 1×3px이며 현재 시험에서는 그대로 보존한다. 이전 v005/v006 정리 기준 파일과 부위 마스크도 같은 방식으로 64×64로 옮겼다. 이 참조 레이어는 이번 축소에 추가 정리 작업을 했다는 의미가 아니다.

## 검수와 판단

저장한 native 파일을 다시 읽어 64×64 크기·프레임·duration·태그·팔레트·PNG 일치·알파를 검사한다. 입력 파일과 보관본의 SHA-256이 일치하는지 확인한다. 실제 사용 색 수와 캐릭터 bounds는 [native_validation.json](../QA/native_validation.json)에 기록한다.

두 프레임에서 깃털·모자·머리카락·얼굴·눈·귀·목·몸통·손·버클·다리·신발·활·활줄·화살통을 실제 64px 캔버스와 확대 이미지로 확인한다. 같은 캐릭터 표시 높이에서 300 원본과 비교하고 반복 재생한다. 축소로 줄어든 명암·사라진 가는 선·눈의 형태 차이는 [visual_review.md](../QA/visual_review.md)에 남긴다.

축소 샘플링 검사 통과와 픽셀 작화 품질은 별도의 판정이다. 해상도 축소만으로 이전 버전의 모든 경계 문제가 정리되었다고 선언하지 않는다. 후속 작화가 필요하면 64×64 기존 픽셀에서 [공통 픽셀 정리 가이드](../../../../../Docs/AI/Art/02_Production/PixelCleanupGuide.md)를 적용하고 새 버전으로 저장한다.
