# 전체 테마와 제작 방향

Hunting Idle · v0.2 · 2026-10-11 / Asia-Seoul

**따뜻한 숲 속의 작은 사냥꾼과 아기자기한 캠프.** 넓은 숲 안에서 작은 사냥꾼이 활을 쏘고, 종마다 다른 동물을 만나며, 수레와 생산 시설에 조금씩 성과가 쌓인다. 오래 켜 두어도 편안한 풍경과 작은 행동의 변화를 중심으로 만든다.

이번 문서는 Notion 아트워크 목록의 「1. 전체 테마와 제작 방향」을 실제 제작에 사용할 기준으로 구체화한다. AD-01 v0.1을 출발점으로 삼고 AD-02~05의 제작 지시를 연결한다. 상태는 **제작 기준 문서 작성 완료 / 새 키아트·비율 시트·UI 시안 제작 대기**다.

후속 제작: [HU-BASE 사냥꾼 32×32 리디자인](../02_Production/HU-BASE_HunterRedesign/README.md)을 2026-10-11에 별도 정본으로 제작했다. 몸과 활을 분리한 정적 베이스이며 기존 Unity 자산은 유지했다. 다음 게임 적용 시 신규 보이는 높이28px와 활 접점을 다시 검수한다.

## 1. 기준과 현재 범위

| 구분 | 확인 내용 | 제작에 주는 조건 |
| --- | --- | --- |
| 현재 게임 | 활 사냥꾼 1명, 토끼·멧돼지·사슴·까치·호랑이·여우 6종, 작은 숲 1곳 | 기존 인물·종 ID·외형을 기준으로 확장 |
| 생활/성장 | 수레, 육포·훈제 고기, 활·시설·탐색 강화 | 활·화살·수레·두 생산 표현이 현재 제작 대상 |
| 기존 캐릭터 | 각 32×32 PNG/Aseprite, 정적 base | 기존 실루엣·무늬·털색을 보존하고 동작 추가 |
| 화면 | 960×540 참조 UI, 640×360 / 1280×720 검수 | 횡방향 사냥길과 우측/하단 오버레이 유지 |
| 아트 연결 | `HuntArtSet`의 배경·소품·메뉴 아이콘 슬롯 구현, 현재 슬롯은 비어 있음 | 정식 PNG 연결 가능 범위와 추가 개발 범위를 구분 |
| 배치 도구 | 화면 편집 창과 `HuntScreenLayout`, 현재 저장된 오버라이드 목록은 비어 있음 | 디자인 시안의 배치 변경은 이후 적용 검수 필요 |

**기존 구현과 원본에서 확인한 사실**은 이 문서의 기준값이다. 신규 색·캔버스 크기·UI 재질·세부 구도는 **제작 시작안**이며, AD-02~05의 실제 시안에서 검수하여 확정한다. 이 문서 작성만으로 새로운 아트가 승인되거나 적용된 것으로 기록하지 않는다.

이전 기획의 총·가방·동물 4종·레시피 3종보다 현재 구현을 우선한다. 배·낚시터 테마, 새 지역, 시간대 변형, 운영체제 투명 창은 이번 기준 작업에 포함하지 않는다.

## 2. 감성의 중심

| 키워드 | 화면에서 표현할 방식 | 검수할 질문 |
| --- | --- | --- |
| 따뜻함 | 녹색 숲, 흙길, 나무와 크림색 UI, 부드러운 좌상단 빛 | 배경과 패널이 한 공간의 재료처럼 보이는가? |
| 작음 | 큰 수관과 나무 사이에 작은 사냥꾼 배치 | 인물을 키우지 않고 숲의 크기를 느낄 수 있는가? |
| 아기자기함 | 귀·꼬리·모자·발·바퀴처럼 읽히는 작은 특징 | 축소 화면에서도 특징이 남는가? |
| 편안한 반복 | 과장하지 않은 걷기·깡충걸음·호흡·생산 변화 | 짧은 반복이 시끄럽거나 피곤하지 않은가? |
| 쌓이는 성과 | 수레 재고, 상품, 짧은 보상/강화 피드백 | 어떤 행동으로 무엇이 늘었는지 읽히는가? |

호랑이와 멧돼지는 덩치와 무게감으로 구분한다. 큰 크기를 유지하면서 눈·입·동작의 공격성을 낮춘다. 기존 동물의 종 특징을 동그란 공통 몸으로 치환하지 않는다. AD-01 이미지 안의 작은 토끼와 나무는 **선·색·명암 설명용 샘플**이며 기존 토끼를 교체할 디자인이 아니다.

사냥 결과는 짧은 반응과 털썩 쓰러짐, 수거·운반·적재로 이어진다. 유혈·상처 확대·해체 묘사 없이 상태 변화를 전달한다. 재료와 상품은 꾸러미·건조 고기·훈제 상품의 요약 아이콘으로 표현한다.

## 3. 화면 구성과 시선의 순서

첫인상은 큰 숲의 덩어리, 행동을 볼 때는 사냥꾼·동물·활과 화살, 관리할 때는 메뉴와 핵심 수치가 읽히게 한다. 배경은 넓게 차지하되 얼굴·무늬·조준 표시보다 대비가 낮아야 한다.

- **상부/중앙:** 큰 나무와 수관, 원경 숲이 공간의 규모를 만든다. 상단 안내판 뒤는 복잡한 가지보다 큰 색 덩어리로 정리한다.
- **하부:** 길은 연속된 수평 바닥으로 유지한다. 발 접점과 화살/사냥감의 상태를 확인할 수 있는 빈 공간을 둔다.
- **좌측:** 수레와 현재 생산 캠프를 한 생활 영역으로 묶는다. 수레와 시설이 같은 위치에 겹치지 않게 한다.
- **우측/하단:** 메뉴와 관리 바가 본 화면 위에 겹친다. 펼침·접힘 때문에 숲·길·사냥꾼의 배치나 본 화면 크기를 변경하지 않는다.
- **전경:** 풀·잎은 가장자리의 깊이 표현에 사용한다. 동물 얼굴, 발, 조준 범위, 화살 경로를 가리지 않는다.

AD-03은 UI 없는 배경 키아트와 검수용 합성본을 함께 만든다. AD-04는 같은 합성 장면을 사용하여 UI만 펼침/접힘으로 바꾼다. 본 화면의 동일 위치를 두 시안에 표시해 배치가 움직이지 않았는지 비교한다.

## 4. 픽셀·외곽선·명암

1. 캐릭터는 기존 32×32 원본 격자에서 시작한다. 기본 외곽선은 원본 기준 1px, 핵심 외곽색은 `#18141F`다. 해상도가 다른 배경 전체에 같은 화면상 선 두께를 기계적으로 강제하지 않는다.
2. 귀·뿔·꼬리·모자·활을 연결된 실루엣으로 남긴다. 눈·입·관절 외의 내부 검은 선은 최소화한다.
3. 좌상단 광원을 제작 기준으로 사용한다. 새 재질은 그림자–기본–빛의 3톤으로 시작하며, 종 식별에 필요한 기존 줄무늬·깃털색·얼굴색을 제거하지 않는다.
4. 넓은 색 덩어리로 명암을 묶는다. 무작위 1px 노이즈, 강한 체커 디더링, 부드러운 그라디언트, 안티앨리어싱·블러를 피한다.
5. 원경의 명암과 채도 대비를 가장 낮추고, 중경·가까운 나무 순서로 깊이를 만든다. 캐릭터의 얼굴과 주요 무늬가 배경에 묻히지 않게 한다.
6. 픽셀 검수용 확대는 정수 배율 + Point/Nearest를 사용한다. 현재 게임은 CanvasScaler와 종별 표시 배율을 사용하므로 모든 화면에서 정수 배율 렌더링이 보장된다고 가정하지 않는다. 3해상도 실화면 검수를 별도로 수행한다.

투명 스프라이트의 외곽은 완전 투명/완전 불투명으로 시작한다. 명시적으로 필요한 FX의 반투명 효과는 별도 자산에서 검토하고 캐릭터 경계와 혼합하지 않는다.

## 5. 색과 재질

색 기준은 **기존 원본의 실제 사용색 → 기존 32색 GPL → 기획 참고색 → 추가 후보** 순서로 확인한다. 기존 GPL은 캐릭터 전체의 실사용색을 완전히 포괄하지 않는다. 새 그림을 맞추기 위해 원본 토끼나 사냥꾼을 일괄 재색칠하지 않는다.

| 역할 | 색 기준 | 상태/사용 |
| --- | --- | --- |
| 핵심 외곽 | `#18141F` | 원본 GPL 및 동물에서 확인 |
| 밝은 털/얼굴 | `#F7EACA` | 원본 GPL, 얼굴과 무늬 판독 |
| 호랑이 | `#E76518` | 기존 오렌지와 원본 명암 우선 |
| 까치 | `#116974` | 기존 청록과 원본 깃털색 우선 |
| 숲 기본 | `#3F614B` | 기획 참고색, 기존 GPL 밖 |
| 잎 | `#78915B` | 기획 참고색, 기존 GPL 밖 |
| 나무 | `#AD7E58` | 기획 참고색, 수레/프레임 재질 연결 |
| 종이/패널 | `#EFE5C8` | 기획 참고색, 글자 뒤의 조용한 면 |
| 보상 금색 | `#ECC96D` | 기획 참고색, 코인·보상·선택 포인트 |
| 보조 버튼 보라 | 차분한 저채도 보라 | 기획상 방향만 있음. HEX는 AD-04에서 대조 후 기록 |

AD-01 후보 팔레트는 기존 4색+기획 5색+제안 9색, 총 18색이다. 대조 결과 기획 5색과 제안 9색은 모두 기존 GPL과 다른 **14색 추가 후보**다. 합친 46색 전체를 자동 채택하지 않는다.

호랑이/까치의 그림자·빛 색은 이미 원본 GPL에 있으므로 기존 색을 먼저 재사용한다. 신규 명암색은 기존 색으로 부족한 재질에 한해 추가하며 `HEX / 이름 / 용도 / 출처 / 채택 상태`를 팔레트 대조 문서에 기록한다. [32색 전체와 후보 대조](AD-01_StyleRules/PaletteAudit.md)를 확인한다.

UI는 나무색 외곽, 종이색 내부, 명확한 어두운 글자를 기본으로 한다. 보라색은 보조 동작, 금색은 선택·성과에 제한적으로 쓰는 시작안이다. 활성·비활성·선택을 색만으로 구분하지 않고 프레임·눌림 위치·마크를 함께 사용한다.

## 6. 캐릭터와 종별 비율

사냥꾼 표시 설정은 `hunterHeight=42`다. 아래 「설정 배율」은 Inspector 값, 「실제 보이는 높이」는 기존 Sprite의 알파 경계와 비율을 반영한 Cycle14 기준이다. **보이는 높이 수치를 Inspector에 그대로 입력하지 않는다.**

| 대상/ID | 설정 배율 | 보이는 높이/사냥꾼 | 반드시 남길 특징 |
| --- | ---: | ---: | --- |
| 사냥꾼 / hunter | 1.00 | 1.00 | 모자·밝은 얼굴·작은 활·걷는 발과 손 |
| 토끼 / rabbit | 0.85 | 약 0.93 | 긴 귀·작은 코·짧은 깡충걸음 |
| 멧돼지 / boar | 1.80 | 약 1.73 | 낮고 넓은 몸·코·짧은 발·무거운 보폭 |
| 사슴 / deer | 2.00 | 약 2.01 | 뿔·목·긴 다리·가벼운 보폭 |
| 까치 / magpie | 0.90 | 약 0.87 | 흰 배·검은 머리·푸른 날개·긴 꼬리 |
| 호랑이 / tiger | 2.60 | 약 2.55 | 큰 머리/발·둥근 귀·줄무늬·꼬리 |
| 여우 / fox | 0.90 | 약 0.87 | 뾰족한 귀·흰 가슴/꼬리 끝·풍성한 꼬리 |

표는 기존 base를 사용하는 비교 기준이다. 새 캔버스·여백·피벗이 도입되면 다시 실제 보이는 높이를 측정한다. 모든 종을 32×32 셀로 제작한다고 게임에서 같은 높이로 표시되는 것은 아니다.

새 프레임에서도 발 접점·몸 중심·손/장비 위치가 흔들리지 않게 고정한다. 뿔·긴 꼬리·운반 포즈가 넘치면 캔버스 크기를 늘리고 기준점을 기록한다. 큰 동물은 월드 운반 중 원래 크기를 유지하며, 창고와 수레의 재고 표시는 작은 관리 아이콘으로 요약한다.

## 7. 움직임과 사냥 결과의 방향

기본 방향은 오른쪽이고 왼쪽은 반전 재사용한다. 종별 걷기·도주의 보폭과 무게감은 구분한다. 모든 상태를 같은 fps로 돌리지 않고 프레임 duration과 이벤트 접점을 남긴다.

- 조준: 활 들기 → 시위 당김 → 유지. 발사 전에는 시위를 놓는 프레임을 재생하지 않는다.
- 발사: release 프레임과 실제 화살 생성 시점을 맞춘다. 활은 별도 소품/레이어로 작업하여 몸과 중복되지 않게 한다.
- 명중/도주: 짧은 반응과 작은 먼지·별로 결과를 읽게 한다. 큰 섬광·화면 흔들림은 최소화한다.
- 쓰러짐: 마지막 포즈와 운반 가능한 downed를 이어 준다. 현재 코드의 -90도 회전과 직접 그린 누운 포즈를 중복 적용하지 않는다.
- 운반/적재: 작은 종은 들기, 큰 종은 견인. 손·끈·사냥감 접점이 이어지고, 적재 완료 시점과 재고 증가가 일치한다.
- 생산/보상: 건조/훈제 상태와 상품을 구분하고, 완료/판매 효과는 실제 완료 이벤트에서 짧게 1회 표시한다.

세부 프레임 수는 Notion의 HU/AN/FX 제작 목록을 따른다. 이번 문서에서는 움직임의 감성과 연결 원칙을 정하며 프레임 작화·AnimationClip 제작·상태 연결은 후속 제작이다.

## 8. 배경과 캠프의 방향

하늘 → 원경 숲 → 중경 수관 → 큰 나무 → 흙길/잔디 → 수레/시설 → 캐릭터/행동 → 제한된 전경의 순서를 디자인한다. 이 순서는 **목표 레이어 구성**이며 현재 코드의 그리기 순서를 변경한 기록이 아니다.

큰 나무는 실루엣이 다른 3종을 시작안으로 하고, 세부 잎보다 큰 수관과 줄기의 덩어리를 우선한다. 길은 반복 경계가 자연스럽고 캐릭터 발이 붙어 보이게 한다. 꽃·돌·버섯·그루터기는 길을 좁히거나 전경을 과밀하게 만들지 않게 배치한다.

좌측 캠프는 수레·건조대·훈제 시설을 같은 재질과 빛으로 연결한다. 현재 생산 진행에 연결된 캠프 표시가 있으므로 시설 PNG를 이를 기준으로 제작한다. 육포와 훈제는 상품과 시설 모습으로 구분하되 **동시에 도는 독립 생산 슬롯 2개를 전제하지 않는다.**

BG/PR 자산은 캐릭터나 UI를 합쳐 그리지 않는다. 수레 전면 테두리처럼 분리된 겹침이 필요한 요소는 별도 납품하고, 현재 슬롯에 없는 레이어는 적용 개발 필요 상태로 기록한다.

## 9. UI 제작 방향

우측 메뉴는 창고·장비·도감·지역·기록·설정 6기능이다. 같은 기능의 하단 바로가기와 우측 아이콘은 그림을 재사용한다. 아이콘은 32×32 제작을 시작안으로 하고 핵심 실루엣이 16×16에서도 구분되는지 확인한다.

공통 관리 창은 나무 외곽/종이 내부, 제목, 닫기, 본문, 스크롤, 하단 동작을 하나의 체계로 만든다. 도감 카드·목표 카드·레시피 선택도 같은 모서리와 여백 언어를 공유한다. 장식은 내용과 버튼을 구분하는 데 필요한 만큼 사용한다.

글자와 수치는 PNG에 넣지 않는다. 한글 폰트는 실제 UI Text로 유지하고, 현재 기본 폰트와 12px 이상 주요 글자 기준에서 작은 화면 판독을 확인한다. UI 크기 조절은 9-slice 또는 모서리/변/중앙 분리로 계획하며 외곽선을 늘려 뭉개지 않는다.

공통 버튼은 기본·가리킴·눌림·비활성을 정의하고 선택 표시를 따로 정의한다. 6개 아이콘마다 상태별 그림을 반복 제작하기보다 공통 프레임으로 처리한다. 공통 패널·버튼 스킨용 `HuntArtSet` 슬롯은 현재 없으므로, AD-04/05는 시안과 자산 설계 후 적용 코드를 연결하는 작업이 필요하다.

## 11. 제작 순서와 완료 판단

1. AD-01 팔레트 대조를 읽고 기존 base와 신규 숲/UI 색을 나란히 검수한다.
2. AD-02로 작은 사냥꾼과 6종의 비율을 고정한다. 토끼와 호랑이를 작은/큰 종의 대표로 먼저 확인한다.
3. AD-03으로 숲·길·좌측 캠프 구도를 잡는다. AD-04/05에 동일 장면을 사용하여 배경과 UI의 대비를 함께 검수한다.
4. 정식 숲 레이어/나무 → 수레·활·화살 → 건조대·훈제 시설 → 공통 UI/메뉴 아이콘 순으로 제작·연결한다. 이는 최신 연결 현황의 제작 순서다. 시설 아트는 원래 목록의 P1 항목이지만 현재 슬롯이 준비되어 있어 정적 캠프 작업에 이어 제작한다.
5. 사냥꾼+토끼의 성공/도주 한 루프를 만든 뒤 호랑이 크기·쓰러짐·견인을 검수하고 나머지 종으로 확장한다.
6. 생산/판매/강화 피드백과 후순위 장식·시간대·장비 외형을 확장한다.

**문서 검수 완료:** 출처, 현재 범위, 색의 채택 상태, 비율, AD별 산출물, 저장 위치와 적용 범위를 확인했다.

**시안 검수 완료 조건:** 실제 원본을 사용한 비교본이 있고, 640×360 / 960×540 / 1280×720에서 얼굴·종·활·아이콘이 읽히며, UI 두 상태의 본 화면 위치가 같고, 새 색/재질·접점·프레임 여백에 대해 검수 기록이 남아야 한다.

**게임 적용 검수 완료 조건:** 목표 슬롯/코드에 연결하고 성공·도주·쓰러짐·작은/큰 운반·적재·생산·메뉴 6개·스크롤을 실제 화면에서 확인해야 한다. 문서 작성이나 시안 PNG 생성으로 이 단계를 완료 처리하지 않는다.
