# 범용 아트워크 제작·QA 가이드

v1.0 · 2026-10-13 · Hunting Idle

캐릭터·동물·장비·배경·건물·소품·UI·애니메이션 작업에 공통으로 사용하는 제작 및 검수 기준이다. 프로젝트의 제작 문서와 Hunter_1254, Hunter_300, Hunter64, MountainSkyLoop, Loghouse의 README·수정 명세·QA 기록에서 반복된 원칙과 실제 실패 사례를 정리했다.

**최신 입력을 확인하고 보존한 뒤, 부위와 레이어의 역할을 정하고, 저장된 결과를 단독 표시·숨김·전체 합성·실제 크기에서 검수한다.** 파일 규격이 맞는 것, 그림이 자연스러운 것, 재생기가 동작하는 것, Unity에 적용된 것은 각각 판정한다.

## 1. 적용 범위와 기준의 우선순위

1. 현재 대화에서 사용자가 지정한 작업 범위·제작 방법·보존 요구를 우선한다. 기존 대화에서 확정한 조건도 이어서 적용한다.
2. 해당 작업의 최신 README·명세·QA 정정 기록으로 현재 입력, 정본, 상태를 확인한다. 과거의 완료 기록보다 후속 검수에서 정정한 판정을 따른다.
3. 공통 감성과 화면 방향은 [ArtDirection.md](../01_ArtDirection/ArtDirection.md), 저장·납품은 [ProductionGuide.md](ProductionGuide.md), 픽셀 정리는 [PixelCleanupGuide.md](PixelCleanupGuide.md)를 함께 적용한다.
4. 이 문서는 여러 작업에 재사용할 절차와 QA 기준을 제공한다. 작업마다 다른 캔버스·팔레트·장비·레이어·접점 좌표는 해당 작업에서 확정한다.

**32×32·64×64·300×300·1254×1254, 17칸 팔레트, 특정 신발 좌표, 8프레임 걷기 등은 개별 작업의 값이다.** 이를 프로젝트 전체의 고정 규격으로 적용하지 않는다. 기존 방향 문서의 활과 최근 Hunter64 실험의 새총처럼 서로 다른 작업 단계도 구분한다. `Try` 실험 결과만으로 정식 자산 규격이나 게임 장비가 변경된 것으로 기록하지 않는다.

## 2. 시작 전: 입력과 수정 범위를 확정한다

### 2.1 실제 파일을 확인한다

- 해당 버전 README에서 디자인 원본, 동작 편집 정본, 출력, 보존본, 최신 QA를 찾는다. 파일명·수정 시각만으로 입력을 고르지 않는다.
- 원본을 열어 캔버스, 색상 모드, 프레임 수, 태그, duration, 팔레트, 레이어 이름·순서·visible·opacity·blend, 셀의 위치를 확인한다. 그룹이 있으면 부모 그룹의 표시 상태도 확인한다.
- 사용자가 수정한 기준 프레임을 이전 원본과 실제 픽셀로 비교한다. 디자인 변경, 포즈 시험, 장비 변경, 표시 상태 변경을 구분한다.
- 후속 프레임의 시험 포즈를 모든 프레임의 공통 디자인으로 자동 복사하지 않는다. 어떤 프레임의 어떤 부위를 기준으로 삼는지 명시한다.
- 마스크·부위 분할·템플릿은 최신 원본에 다시 맞춘다. 옛 좌표 경계를 재사용할 때 경계 열·행에 추가된 픽셀이 빠지지 않는지 확인한다.

### 2.2 바꿀 것과 보존할 것을 적는다

| 구분 | 시작할 때 정할 내용 |
| --- | --- |
| 입력 | 실제 사용할 파일·버전·프레임·레이어 |
| 수정 범위 | 디자인, 색·경계 정리, 해상도 비교, 레이어 분리, 동작 제작 중 해당 항목 |
| 보존 범위 | 원본 파일, 얼굴·의상·장비 인상, 기준 자세, 팔레트, 기존 프레임·시간 등 |
| 출력 규격 | 편집 캔버스, 논리 도트, PNG 크기, 셀 크기, 실제 표시 크기 |
| 접점 | 바닥, 몸 중심, 손·장비, 관절, 운반 대상, 건물·소품 배치 기준 |
| 제작 방법 | 기존 픽셀 직접 편집, 신규 작화, 생성 시안 활용 등 실제 허용된 방법 |
| 완료 범위 | 시안·레이어 검수·연속 동작·납품·Unity 적용 중 이번에 수행할 단계 |

수정 전 원본은 `Source/` 또는 `Backups/`에 바이트 그대로 보존하고 SHA-256을 기록한다. 현재 정본과 보존본의 역할을 README에 적는다. 별도 재시도는 기존 결과를 유지한 새 파일 또는 새 버전으로 만든다. 사용자가 같은 버전의 수정을 지정했다면 변경 전 보존본을 남기고 현재 README를 갱신한다.

## 3. 디자인·색·크기의 공통 원칙

- 따뜻한 숲, 작은 사냥꾼, 아기자기한 캠프와 편안한 반복을 공통 방향으로 삼는다. 실제 인상은 같은 표시 크기의 전후 비교와 장면 합성으로 확인한다.
- 얼굴·눈·귀·모자·깃털·꼬리·무늬·의상·장비처럼 정체성을 설명하는 특징을 유지한다. 색 수를 줄이거나 작은 크기로 바꿀 때 특징이 사라지지 않는지 따로 확인한다.
- 기존 자산 수정은 실제 사용색을 먼저 확인하고 기존 팔레트를 우선한다. 신규 색은 용도·출처·채택 상태를 기록한다. 한 실험의 색을 공통 팔레트로 자동 채택하지 않는다.
- 팔레트 슬롯 수, 투명 슬롯 수, 실제 불투명 사용색 수, 합성에서 보이는 색 수를 구분한다. Indexed와 RGB 작업의 검사 방식도 구분한다.
- 픽셀 작업의 캐릭터·소품 경계는 완전 투명/완전 불투명을 기본으로 한다. 반투명 FX 등 의도한 예외는 자산·레이어별로 기록한다.
- 캔버스 크기, 표현상의 논리 도트, 출력 확대 배율, 실제 게임 표시 높이는 서로 다르다. 픽셀 검수 확대는 정수 배율과 Point/Nearest를 사용한다.
- 해상도 비교·축소는 새 작화나 경계 정리와 구분한다. 축소만으로 원본의 형태 차이·잔색·포즈 불일치가 해결되었다고 판단하지 않는다.
- 프레임마다 크롭·배율을 바꿔 흔들림을 만들지 않는다. 같은 클립은 공통 배율과 접점을 사용하고, 숙인 포즈를 선 포즈 높이까지 늘리지 않는다.
- 생성 시트를 분할할 때는 실제 실루엣과 빈 구간을 확인한다. 균등 셀 경계를 가정해 깃털·부츠·손·화살을 자르지 않는다.

## 4. 레이어와 부위를 나누는 기준

### 4.1 레이어의 역할을 먼저 정한다

| 역할 | 관리·출력 기준 |
| --- | --- |
| 게임용 그림 | 캐릭터 부위, 현재 장비, 배경, 건물, 교체 소품 등. 서로 따로 움직이거나 교체할 요소는 역할을 분리한다. |
| 보존 장비·이전 디자인 | 사용자 요구에 따라 보존한다. 기본 표시와 게임용 export 포함 여부를 명시한다. |
| 참조·전후 비교 | 어떤 시점의 참고인지 적고, 현재 결과의 참조라면 최신 합성과 맞춘다. 게임용 export에서 제외한다. |
| 마스크·지시·격자 | 실제 수정 범위나 좌표 기준을 설명한다. 그림과 다른 안내 색을 쓰며 게임용 export에서 제외한다. |
| 의도한 빈 레이어 | 미해금 요소·작업 공간 등 이유와 기본 표시를 적는다. 빈 상태를 오류 또는 완성 그림으로 계산하지 않는다. |
| 접점 확인용 소품 | 시연용 동물·짐·수레 등임을 표시하고 캐릭터 단독 출력에서 제외한다. |

최종 레이어 구성은 해당 작업의 요구를 따른다. 작업 중 임시로 팔·다리·장비를 더 나누더라도 원래 레이어 구조 유지가 조건이면 최종 파일에 그 구조로 합친다. 레이어 이름·순서·불투명도·블렌드 설정은 변경 필요가 확인된 범위에서 수정한다.

**편집 파일의 기본 visible 상태와 export의 표시 정책을 따로 적는다.** 사용자가 장비만 보도록 격리해 저장한 원본과 전체 캐릭터 PNG는 표시 대상이 다를 수 있다. QA용 가시성 전환은 복사본에서 수행하거나 저장하지 않고 원래 상태를 복원한다.

### 4.2 가려진 면을 완성한 뒤 움직인다

- 팔을 분리하기 전에 팔 뒤의 상의·벨트 면을 확인하고 필요한 영역을 복원한다. 팔에 가려진 옷 픽셀까지 잘라 옮겨 사각 투명 구멍을 만들지 않는다.
- 건물·소품을 분리할 때 앞 요소 아래의 배경이 필요한 표시 상태를 정하고, 해당 상태에서 누락이나 제거 자국이 드러나지 않게 만든다.
- 원본에 존재하지 않던 숨은 숲·벽·바닥을 보완했다면 추정 보완이라고 기록한다. 실제 원본 픽셀의 복구와 구분한다.
- 색만으로 부위를 분리하지 않는다. 같은 갈색이 머리카락·가죽·목재에 쓰일 수 있으므로 위치, 실루엣, 재질, 마스크를 함께 사용한다.
- 앞뒤 발·옷자락·팔·장비의 가림 순서를 정한다. 가려져 보이는 픽셀 수가 줄어든 것과 원본 템플릿에서 픽셀이 누락된 것을 구분한다.
- 모든 투명 공간을 채우지 않는다. 옷 안의 잘못된 구멍과 활줄 안쪽·팔 사이·다리 사이·바퀴 구멍의 정상 공간을 의미로 판단한다.

## 5. 기존 픽셀의 면·경계 정리

상세 방법은 [PixelCleanupGuide.md](PixelCleanupGuide.md)를 따른다.

1. 대표 부위의 수정 전후 기준 예시를 만든다. 정리한 잔색·띠·돌출과 남긴 명암·디테일을 설명한다.
2. 재질 면, 수정 가능한 경계, 보존 디테일을 실제 프레임에 맞는 마스크로 구분한다.
3. 고립 점뿐 아니라 면에 붙은 가는 색 띠, 여러 픽셀 돌출·패임, 선 두께, 사선·곡선의 계단 진행을 함께 고친다.
4. 눈·귀·버클·활줄 등의 의미와 형태를 보존한다. 검정 윤곽·투명 영역 전체를 일괄 보호해 잘못된 경계까지 남기지 않는다.
5. 같은 기준을 다른 프레임의 움직인 위치에도 적용하고 전신을 다시 확인한다.

색 수 제한, 양자화, 이웃 다수결, 형태 필터, 구멍 탐지는 후보 확인과 범위 검사에 사용할 수 있다. 그 수치만으로 작화 완료를 판정하지 않는다. 모든 계단 길이를 같게 만들거나 캔버스 전체에 임의의 낮은 해상도 격자를 강제하지 않는다.

기존 픽셀 정리와 디자인 보존 동작 작업은 Aseprite 픽셀을 직접 수정한다. 해당 작업에서 금지된 이미지 재생성·블러·안티앨리어싱·디더링·색 평균 보간을 사용하지 않는다. 신규 컨셉이나 허용된 배경 보완에 생성 시안을 사용한 경우 원본·프롬프트·보완 범위·최종 픽셀 처리 과정을 기록한다. 생성 보완과 기존 픽셀 수정을 같은 방법으로 보고하지 않는다.

## 6. 애니메이션: 동작·접점·시간을 함께 설계한다

### 6.1 부위의 움직임과 연결

- 움직일 부위, 기준점, 이동·변형량, 가림 순서를 정한다. 좌표는 원점, 축 방향, 단위, 0/1부터 시작하는지, 범위 끝 포함 여부를 적는다.
- 머리 형태를 보존하는 작업은 모자·깃털·머리카락·얼굴·귀·눈을 함께 움직인다. 얼굴 표정 등 별도 변형이 작업 범위라면 그 예외를 명시한다.
- 팔은 어깨→팔꿈치→손목, 다리는 골반→무릎→바짓단→발을 연결한다. 손을 옮기면 장비 그립을, 부츠를 옮기면 바짓단과 무릎을 함께 맞춘다.
- 장비는 역할별 접점을 따른다. 손에 든 무기는 손, 착용 장비·자루는 몸과 부착점, 견인줄·운반 대상은 손과 대상의 접점을 기준으로 움직인다.
- 보행은 착지→몸 낮춤→발 통과→몸 상승→반대 착지의 연결을 확인한다. 지지 발과 들린 발, 무릎 굽힘, 반대 팔, 몸 높낮이, 자락·자루의 지연을 실제 작은 크기에서 읽을 수 있어야 한다.
- 교차 발이 한 발처럼 보이면 앞뒤 가림, 들림 높이, 발끝·커프 연결을 조정한다. 숫자로 이동을 확인한 뒤 전체 캐릭터와 밝은 배경에서 다시 판정한다.

### 6.2 프레임과 재생 규칙

- 키포즈 작업본과 연속 재생본을 구분한다. 의도한 빈 중간 프레임은 README에 적고 완성 루프로 표시하지 않는다. 완성 반복 구간에는 캐릭터가 사라지는 의도하지 않은 빈 프레임이 없어야 한다.
- 처음과 같은 닫힘 참조 프레임을 별도로 둘 수 있다. 반복 구간에 중복 포함해 첫 자세가 두 번 머무는지 확인하고, 필요하면 별도 태그로 제외한다.
- 반복·단발·마지막 자세 유지 방식, 태그 범위, 각 duration, 총시간을 기록한다. GIF가 반복된다는 이유로 단발·유지 동작의 종료 규칙이 확인된 것으로 판단하지 않는다.
- 마지막→처음 연결과 상태 간 전환을 확인한다. 조준→발사, 수거→운반, 운반→적재에서 손·장비·몸 크기·바닥이 튀지 않아야 한다.
- release·pickup·detach·load_complete 같은 이벤트는 프레임과 발생 시점을 기록한다. 제작 메타의 이벤트와 실제 게임 로직 연결은 구분한다.
- 자동 trim이나 프레임마다 바뀌는 투명 여백으로 접점이 움직이지 않게 한다. 크롭 출력이 필요하면 원래 캔버스의 오프셋·피벗을 함께 남긴다.

## 7. 배경·건물·소품·UI의 추가 기준

| 대상 | 추가 제작·QA 항목 |

## 8. 공통 QA: 순서와 필수 확인

### 8.1 저장 파일을 독립적으로 다시 읽는다

편집 중 메모리나 제작 스크립트의 계산값만 검사하지 않는다. 저장된 편집 정본을 다시 열어 실제 셀·레이어·태그·duration·팔레트·알파·좌표를 읽고 출력을 재생성해 비교한다.

| 검사 | 확인할 내용 |
| --- | --- |
| 파일 구조 | 캔버스·색상 모드·레이어/그룹·셀 위치·프레임 수·태그·duration |
| 표시 정책 | 편집 기본 visible과 export 대상, 부모 그룹·opacity·blend, 안내 레이어 제외 |
| 출력 대응 | 합성 PNG, 레이어 PNG, 개별 프레임, 시트, JSON의 범위·순서·좌표 일치 |
| 색·알파 | 팔레트 슬롯과 실사용색, 투명 인덱스, 의도하지 않은 새 색·부분 알파 |
| 동작 | 기준 자세, 부위 이동, 접지·그립·관절, 반복 범위·총시간·이벤트 |
| 보존 | 입력/보존본 해시, 수정 금지 파일, 지정한 레이어·프레임·영역의 차이 |

무손실 PNG와 동일한 표시 정책의 native 렌더는 픽셀 일치를 확인한다. 최근접 확대는 규정 배율의 일치를 확인한다. GIF 등 팔레트·시간 양자화가 가능한 출력은 실제 변환 조건과 허용 차이를 명시한다. 차이 수치는 무엇을 비교한 값인지 적는다.

### 8.2 전 레이어를 한 개씩 단독 visible로 검수한다 — 필수

**전체 합성이 정상이어도 각 레이어의 단독 표시 검수는 수행한다.** 기존 레이어 PNG만 보는 것에 그치지 않고, 저장된 Aseprite의 실제 표시 상태를 전환해 다시 렌더한 결과를 확인한다.

1. 레이어/그룹 인벤토리를 만들고 이름·역할·기본 visible·셀 유무·검수 프레임 범위를 적는다.
2. 검수 복사본에서 대상 레이어만 visible로 설정한다. 필요한 부모 그룹만 켜고 형제·참조·마스크·격자·이전 장비 등 다른 그림은 끈다. opacity·blend는 원래 값을 유지한다. 그룹은 내부 개별 레이어도 검사한다.
3. 단독 상태를 저장 후 재개봉하거나 독립 재로드하고, 실제 visible 값과 출력 경로를 기록한다. 상태별 `.aseprite` 또는 재현 가능한 상태 기록·스크립트를 남긴다.
4. 투명 PNG, 체크 배경, 밝은/어두운 단색 배경, 원래 표시 크기, Point/Nearest 확대에서 내용과 경계를 확인한다. 검수 배경은 그림 파일에 합치지 않는다.
5. 애니메이션은 각 레이어의 모든 프레임을 확인한다. contact 시트로 전체를 보되 의심 부위는 개별 프레임에서 확대한다. linked cel이 있으면 연결·좌표·duration도 확인한다.
6. 단독 픽셀의 대상 외 혼입, 외곽 잘림, 잔색 띠, 부착점 단절, 부자연스러운 투명 구멍, 미복원 면, 반복 복사 자국을 평가한다.
7. 기본 숨김 레이어도 인벤토리에서 빼지 않는다. 이전 장비·참조·가이드의 역할과 내용, 출력 제외를 확인한다. 의도한 빈 레이어는 셀 없음/완전 투명 여부를 확인하고 이유를 적는다.
8. 게임용 레이어 단독 판정과 전체 합성 판정을 따로 기록한다. 숨긴 보존 레이어의 검토 결과는 현재 게임용 작화 통과와 구분한다.

몸통·팔처럼 합성으로 연결되는 부위가 단독으로 완전한 캐릭터일 필요는 없다. 다른 레이어와 결합하도록 설계된 형태·투명 여백·블렌드 의존은 명시하고 조합 상태에서 확인한다. 단독 검수의 목적은 **그 레이어의 역할에 맞는 픽셀이 온전히 있고, 불필요한 픽셀과 누락이 없는지** 확인하는 것이다.

CLI/Lua로 `isVisible`을 설정했다면 실제 수행한 방법을 적는다. 키보드 단축키나 UI 조작을 실행하지 않았다면 실행한 것으로 보고하지 않는다. 검수 종료 후 정본의 기본 표시와 사용자 편집 상태를 복원하고 저장 여부를 확인한다.

### 8.3 한 레이어씩 숨겨 가려진 영역을 검수한다 — 필수

게임용 export의 기본 조합에서 표시 레이어를 하나씩 숨긴 결과를 확인한다. 기본 숨김인 보존·안내 레이어를 모두 켜는 방식으로 기본 조합을 바꾸지 않는다.

- 팔을 숨긴 상의, 건물을 숨긴 숲·마당, 소품을 숨긴 벽·바닥, 주요 산을 숨긴 먼 능선을 확인한다.
- 앞 요소가 가리던 빈칸, 제거 자국, 사각 패치, 반복 띠, 다른 물체의 잔여 픽셀을 찾는다.
- 독립 이동·교체·해금으로 실제 노출될 면은 필요한 범위까지 완성한다. 노출하지 않는 구조적 예외는 이유를 기록한다.
- 배경→배경+건물→소품 포함, 몸→팔→장비처럼 접점이 중요한 조합도 확인한다. 최종 가림 순서와 부착점이 맞는지 본다.
- 투명 구멍 탐지값은 실제 형태와 대조한다. 정상적인 물체 사이 공간까지 자동으로 채우지 않는다.

### 8.4 전체 그림과 모든 프레임을 검수한다 — 필수

- 캐릭터는 머리부터 신발·장비까지, 장면은 전체 캔버스의 건물·배경·소품을 확인한다. 수정한 영역 외에 인접 경계와 접점도 본다.
- 전후를 같은 위치·배율·배경에서 비교한다. 해상도가 다르면 같은 실제 표시 크기의 비교도 만든다.
- 확대에서 잔색·띠·돌출·패임·선 두께·구멍·가림을, 원래 표시 크기에서 인상·실루엣·얼굴·발·장비·아이콘의 판독을 확인한다.
- 애니메이션은 반복 마지막→처음, 기준 자세, 반대쪽 팔·다리, 교차 프레임, 가장 숙인 자세, 이벤트 프레임을 포함해 전 프레임을 본다.
- 반복 동작은 최소 두 주기 재생하며 경계 점프·빈 프레임·발 미끄러짐·장비 분리·명암 흔들림을 확인한다. 단발과 마지막 유지 동작은 종료 상태를 별도로 확인한다.
- 정적 자산의 재생은 `해당 없음`이다. 애니메이션을 실제 재생하지 못했다면 `미검수`다. 두 상태를 구분한다.

### 8.5 재생기와 실제 게임 적용을 구분한다

재생기를 만들거나 수정했다면 실제 브라우저에서 이미지 로드, 동작 선택, 모든 프레임 이동, 반복/단발/유지, 속도·크기·배경 전환, 링크, 콘솔 오류, 작은 화면 잘림을 확인한다. 비교 재생기는 클립 내부의 배율과 비교 기준 높이를 고정한다. HTML 문법·파일 경로 검사만 수행했다면 브라우저 실행 검수로 기록하지 않는다.

Unity 적용이 작업 범위라면 Sprite 참조·GUID·`.meta`·기존 importer를 확인한 뒤 필요한 출력만 전달한다. Point·무압축·MipMap off 등의 값은 제작 제안과 실제 설정을 구분하고, PPU·pivot·slice·border는 자산과 현재 표시 방식에 맞춰 확정한다.

현재 프로젝트의 화면 비교 기준은 640×360 / 960×540 / 1280×720이다. 실제 적용 단계에서 대상 자산과 관련된 사냥 상태·운반·적재·메뉴·스크롤·UI 펼침/접힘을 실화면으로 확인한다. 배율·알파 경계·Sprite rect가 바뀌면 실제 보이는 높이와 접점도 다시 측정한다. 제작 메타 작성, 재생기 통과, PNG 저장은 Unity 연결·실화면 통과의 근거가 될 수 없다.

## 9. 저장·버전·납품

새 작업의 경로와 이름은 [ProductionGuide.md](ProductionGuide.md)를 따른다. 현재 경로를 임의로 정리하거나 기존 정본·Unity 자산을 중복 이관하지 않는다.

```text
ArtSource/Try/<실험명>/vNNN/       # 비교 실험 예시
  README.md                        # 입력·정본·현재 상태·최신 QA
  Source/                          # 실제 입력 보존본·생성 원본
  Reference/                       # 디자인 참고·전후 기준 예시
  Masks/                           # 실제 부위·보존·수정 경계
  Work/ 또는 Clips/<작업ID>/         # 편집 정본; 작업 구조에 맞게 선택
  Frames/                          # 개별 프레임; 애니메이션일 때
  Export/                          # 합성·분리 PNG·시트·제작 메타
  Previews/                        # 전후·확대·재생기
  Prompts/ 또는 Scripts/            # 실제 사용한 지시·제작 코드
  QA/
    visual_review.md               # 부위·레이어·프레임별 판단
    LayerReview/
      States/                      # 표시 상태 파일 또는 재현 기록
      Solo/                        # 한 레이어만 visible
      Hidden/                      # 한 레이어만 숨김
      Crops/                       # 같은 위치의 경계 확대
      Repeats/                     # 반복 자산 검수; 해당할 때
```

위 구조는 예시다. 클립 안에 `Source/Frames/Export/Masks`가 있는 기존 작업은 그 구조를 유지한다. 실제 필요한 폴더만 만들고 빈 명세·빈 QA 파일을 완성 기록처럼 추가하지 않는다. 정식 시안은 `Drafts`, 확정한 신규 편집 정본은 `Production`, Unity 출력은 `Assets/Art/Sprites`에서 관리한다.

각 작업 README는 편집 정본을 명확히 지정한다. 디자인 원본, 동작별 정본, 별도 retry, 과거 보존본의 역할을 구분한다. 파일명은 안정된 자산명과 `v001/v002` 등의 버전을 사용한다. `final2/new`처럼 역할이 불분명한 이름을 늘리지 않는다.

다운로드 묶음은 현재 정본·출력·메타·필요한 QA와 안내를 포함한다. 상대 링크와 재생기 자원이 묶음 안에서 열리는지 확인하고, 로컬에만 남긴 과거 기록·대형 원본이 있으면 패키지 안내에 적는다. 편집 원본과 게임용 PNG에 마스크·격자·검수 배경이 섞이지 않게 한다.

### 10.3 작업 요청에 붙일 공통 지시

```text
ArtworkGuide.md와 해당 작업의 최신 README·QA를 먼저 확인한다.
현재 입력과 수정 범위·보존 조건을 기록하고 원본을 동결한다.
기준 예시와 실제 부위 마스크를 사용해 허용된 방법으로 편집한다.
저장 파일을 독립 재개봉해 출력·팔레트·태그·시간·접점을 검사한다.
전체 레이어·전체 프레임을 한 레이어만 visible로 검수한다.
한 레이어씩 숨겨 가려진 면을 확인한 뒤 전체 합성을 다시 검수한다.
실제 표시 크기와 필요한 재생/반복/브라우저 검수를 수행한다.
QA에는 근거와 남은 문제를 기록하고 수행한 단계만 완료로 보고한다.
```

## 11. 완료 전에 확인할 체크리스트

- [ ] 최신 입력의 파일·기준 프레임·부위를 실제 확인했다.
- [ ] 이전 판정 정정과 남은 문제를 읽고 이번 범위를 정했다.
- [ ] 입력/기존 결과를 보존하고 해시와 정본 역할을 기록했다.
- [ ] 최신 디자인에 맞는 마스크·분할 경계를 사용했다.
- [ ] 캔버스·논리 도트·출력·실제 표시 크기를 구분했다.
- [ ] 작업 방법과 생성 활용 여부·범위를 정확히 기록했다.
- [ ] 레이어 역할·순서·기본 표시·export 정책을 기록했다.
- [ ] 움직이거나 제거할 요소 아래의 필요한 면을 완성했다.
- [ ] 저장 파일을 다시 읽어 구조와 대응 출력을 검사했다.
- [ ] 모든 레이어와 모든 프레임을 단독 visible로 확인했다.
- [ ] 한 레이어씩 숨겨 가려진 면·혼입·제거 자국을 확인했다.
- [ ] 정상 투명 공간·의도한 가림·빈 레이어를 결함과 구분했다.
- [ ] 전체 부위·전체 프레임을 같은 조건의 전후·확대로 확인했다.
- [ ] 실제 표시 크기에서 인상·실루엣·접점·판독을 확인했다.
- [ ] 필요한 반복/단발/유지·상태 전환·배경 이음새를 확인했다.
- [ ] 재생기/Unity 검수는 수행한 범위와 미수행 범위를 구분했다.
- [ ] 정본의 표시 상태를 복원하고 원본 보존을 확인했다.
- [ ] README·QA·납품 링크가 현재 파일과 맞으며 남은 문제를 적었다.

작업과 관계없는 항목은 이유를 적어 `해당 없음`으로 처리한다. 이번 완료 범위에 필요한 QA가 `수정 필요` 또는 `미검수`라면 해당 범위를 완료로 보고하지 않는다. 전달할 때 편집 정본, 전후 비교 또는 재생기, 최신 QA, 해결 범위와 남은 문제를 함께 제시한다.
