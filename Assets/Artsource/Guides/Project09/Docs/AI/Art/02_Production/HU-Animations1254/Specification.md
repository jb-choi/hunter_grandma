# 사냥꾼 애니메이션 1254×1254 실험 제작 명세

v0.1 · 2026-10-11 · HU-01~08 · 실험용 제작 기준

**첨부한 사냥꾼의 외형을 유지하면서 1254×1254 프레임으로 8개 동작을 검토한다.** 이번 결과는 32×32를 대체할지 판단하는 비교 자료다. 정식 제작 해상도 변경이나 Unity 적용 완료를 의미하지 않는다.

Notion 「UI」의 `3. 사냥꾼 애니메이션 제작 목록`에 있는 ID·태그·프레임 수를 유지한다. 합계는 **오른쪽 원본 36프레임**이다. 아래 duration·접점·이벤트 배치는 이번 실험의 제작 제안이며 Notion에서 이미 확정한 수치가 아니다.

## 1. 캐릭터와 프레임 계약

- 모든 프레임은 1254×1254 RGBA PNG로 저장한다. 생성 시트에서 포즈를 추출한 뒤 클립 안에서 하나의 배율로 정규화한다. 포즈별 높이에 맞춰 각각 늘리지 않는다. 동작별 기준점·배율 차이는 메타에 남기고 정식 적용 전에 연결한다.
- 실험 시작값은 **서 있는 캐릭터 높이 980px, 발 기준선 y=1115px 경계**다. 실제 생성 출력 검수 후 확정값을 QA에 기록한다. 같은 clip 안에서는 하나의 배율을 유지하며, 앉거나 허리를 굽힌 collect/load 포즈를 서 있는 높이로 늘리지 않는다. 자세에 따른 짧아진 높이와 발 들기·몸의 상하 움직임을 보존한다.
- 둥근 녹색 모자와 챙, 크림색 깃털, 금갈색 머리, 밝은 얼굴과 작은 눈, 목깃, 대각선 가죽 끈, 벨트 버클, 튜닉 자락, 접힌 부츠를 유지한다. 각 프레임에서 얼굴·복장·활의 재질이 바뀌지 않게 한다.
- 기본은 오른쪽을 보는 측면이다. 왼쪽 이동은 같은 프레임의 반전으로 시험하며 화살통·잡는 손의 비대칭이 문제가 되는지는 별도 검수한다. 왼쪽 작화 36장을 제작했다고 계산하지 않는다.
- 각 상태의 발 접점과 몸 중심을 기록한다. 호흡·걷기의 의도한 상하 움직임과 캔버스 정렬 오차를 구분한다. 프레임마다 투명 여백이 달라져도 피벗은 고정한다.
- 활을 그림에 포함하는 실험본은 별도 런타임 활과 중복 표시하지 않게 한다. 발사 이후 날아가는 화살은 별도 오브젝트로 연결할 수 있도록 release 위치를 기록한다.
- 좌표는 PNG 좌상단 원점 `(x, y)`, 단위 px로 기록한다. `feet`, `bow_grip`, `arrow_release`, `carry_contact`, `drag_contact`, `load_contact`는 실제 프레임에 맞춰 측정한다. 추정 좌표를 완료값으로 기록하지 않는다.
- 작은 사냥감·큰 사냥감·수레는 사냥꾼 몸과 분리해 유지한다. 시연용 합성본을 만들면 해당 동물/소품을 별도 레이어로 보존한다.

## 2. 제작 목록과 권장 타이밍

프레임 번호는 **1부터 시작**하며 이벤트 시점은 해당 프레임이 표시되기 시작할 때를 뜻한다.

| ID / 태그 | 수 | 동작과 포즈 구성 | 권장 duration | 재생·이벤트 |
| --- | ---: | --- | --- | --- |
| HU-01 `idle` | 2 | ① 기본 대기 ② 작은 호흡·옷자락 변화 | 500 / 500 ms | 1초 루프. 바닥과 모자·얼굴 크기 고정 |
| HU-02 `walk` | 6 | ① 오른발 접지 ② 하강 ③ 교차 ④ 왼발 접지 ⑤ 하강 ⑥ 교차 | 각 120 ms | 720 ms 루프. 6→1의 부드러운 연결과 발 미끄러짐 검수 |
| HU-03 `focus` | 4 | ① 활을 들기 ② 손 정렬 ③ 당기기 ④ 완전히 당긴 조준 | 각 150 ms | 600 ms 진입 후 F04 유지. 집중 상태가 끝날 때 `shoot`로 전환 |
| HU-04 `shoot` | 4 | ① 줄을 놓기 ② 반동 ③ 팔·활 회복 ④ 회복 완료 | 각 100 ms | 400 ms 단발. **F01 시작=release**, 이후 화살은 별도 이동 |
| HU-05 `collect` | 4 | ① 기본 대기 ② 몸 굽히기 ③ 웅크려 손 뻗기 ④ 일어나 운반 자세 | 각 150 ms | 600 ms 단발. **F03 시작=pickup**, F04 완료 후 운반 전환 |
| HU-06 `carry_small` | 6 | 걷기 6포즈를 바탕으로 양손/운반 접점을 고정하고 작은 하중 표현 | 각 140 ms | 840 ms 루프. 사냥감 위치가 손에서 떨어지거나 얼굴을 가리지 않게 검수 |
| HU-07 `drag_large` | 6 | 낮은 중심·당기는 팔·뒤로 남는 하중을 표현하는 6포즈 | 각 160 ms | 960 ms 루프. 손과 끌기 접점 유지, 큰 사냥감은 바닥에서 이동 |
| HU-08 `load` | 4 | ① 수레에 접근한 운반 자세 ② 들어 올리기/당기기 ③ 내려놓기 ④ 손을 놓고 복귀 | 각 250 ms | 1초 단발. **F03 시작=detach** 시각 이벤트, **F04 종료=load_complete** |

`load` 4장은 공통 적재 동작이다. 작은 사냥감과 큰 사냥감에 완전히 다른 동작을 추가하면 36프레임 범위를 넘는 확장 작업으로 기록한다.

`focus`의 F04는 무한 루프가 아니라 마지막 포즈 유지다. 현재 기본 집중 1.5초에서는 진입 600 ms 이후 남은 900 ms를 유지한다. 활 Lv.5에서 집중 시간이 900 ms라면 남은 300 ms를 유지한다. 이후 집중 시간이 더 짧아지는 설계가 생기면 4프레임 진입 시간을 비례 축소하는 방식을 적용 검토한다.

`shoot` F01을 release로 정한 이유는 현재 로직이 `Shooting` 진입과 동시에 화살을 출발시키기 때문이다. 화살을 놓기 전 준비 동작은 `focus`에서 표현한다. F02/F03에서 release하는 연출을 선택하면 화살 타이밍 연결도 함께 바꿔야 한다.

## 3. 현재 게임 흐름과 적용 시 필요한 연결

| 게임 상태 | 대응 작화 | 현재 코드의 동작 | 애니메이션 연결 시 요구 |
| --- | --- | --- | --- |
| `Searching` | `walk` / 정지 시 `idle` | 사냥꾼이 두 순찰 지점 사이를 이동 | 실제 이동 여부로 walk/idle 선택 |
| `Entering` | `idle` | 동물이 걸어 들어오며 사냥꾼은 오른쪽을 봄 | 갑작스러운 프레임 리셋 없이 idle 연결 |
| `Focusing` | `focus` | 기본 1.5초, 활 레벨에 따라 단축 | 조준 진입 후 마지막 포즈 유지 |
| `Shooting` | `shoot` | 진입 즉시 화살 출발, 0.4초 후 성공/실패 판정 | F01 release와 화살 출발 일치 |
| `Fallen` / `Fleeing` | `idle` | 쓰러짐 대기 0.7초 또는 도주 대기 | 잘못된 collect 재생 방지 |
| `Collecting` | `walk` → `collect` | 쓰러진 동물까지 이동 후 곧바로 `Carrying` | **현재 별도 줍기 시간 없음.** 도착 후 collect 단발을 위한 시각/로직 연결 필요 |
| `Carrying` | `carry_small` / `drag_large` | 사냥감을 사냥꾼 위치에 붙여 수레로 이동 | 동물 크기에 맞는 태그와 프레임별 접점 연결 |
| `Loading` | `load` | 1초 뒤 보관량·적재량 증가 후 탐색 복귀 | detach는 시각 처리, 보상은 완료 시 한 번만 유지 |

현재는 사냥꾼 정적 Sprite 한 장을 `Image`로 보여준다. 프레임 애니메이션 플레이어·이벤트 연결·개별 동작 태그 소비는 아직 구현되어 있지 않다. 메타데이터와 미리보기 파일이 있어도 런타임 작동 완료로 표시하지 않는다.

작은 사냥감/큰 사냥감의 현재 구분은 표시 높이가 `hunterHeight` 이하인지 여부다. 설정상 토끼 0.85배, 까치 0.9배, 여우 0.9배는 작은 운반; 멧돼지 1.8배, 사슴 2배, 호랑이 2.6배는 큰 끌기로 시험할 수 있다. 현재 코드는 작은 동물을 사냥꾼 높이의 35%만큼 올리고, 큰 동물은 올리지 않는다. 이 위치식은 손을 측정한 접점이 아니므로 신규 그림과 실제 겹침을 다시 확인한다.

## 4. 표시 크기와 해상도 선택 검수

1254×1254는 원본 캔버스 크기다. 게임에서 사냥꾼이 1254px 높이로 표시된다는 뜻은 아니다.

현재 960×540 기준 UI에서 `hunterHeight=42`, 사냥꾼 Rect는 58×68, `preserveAspect=true`, 배율은 `42/68`이다. **전체 1254×1254 정사각형을 그대로 연결하면 표시 사각형은 약 35.82×35.82px**가 된다. 실제 캐릭터 높이는 여기에 `불투명 영역 높이 / 1254`를 곱한 값이다. 예를 들어 그림의 몸이 캔버스 높이 1000px를 차지하면 실제 표시는 약 28.56px다. 예시는 실측 좌표를 대신하지 않는다.

| 비교 크기 | 검수 목적 |
| --- | --- |
| 원본 1254×1254 | 외형·프레임별 일관성·투명 테두리·손/활 접점 |
| 실제 캐릭터 높이 42px | 현재 게임의 목표 크기에서 얼굴·모자·동작이 읽히는지 |
| 실제 캐릭터 높이 68px | 현재 설정 범위 상한에서 읽힘과 동물 상대 크기 |
| 실제 캐릭터 높이 96px | 확대 연출/레이아웃 변경을 가정한 비교용; 현재 적용 크기로 간주하지 않음 |

작은 표시 크기에서는 Point와 Bilinear를 각각 비교한다. 현재 runtime은 Sprite texture에 Point를 강제한다. 큰 원본이 가진 도트 모양이 작은 표시에서 고르게 남는지, 미세한 명암이 떨리는지, 얼굴과 활 줄이 사라지는지를 확인하고 실험 결과에 따라 필터 정책을 결정한다.

같은 캐릭터 표시 높이에서 기존 32×32 후보와 비교한다. 캔버스 크기만 맞춰 서로 다른 몸 크기를 비교하면 해상도 선택 근거가 되지 않는다. 다음 항목을 모두 검토한 후 정식 크기를 선택한다.

- 기본 외형의 매력이 실제 게임 크기에서도 유지되는가.
- 6프레임 이동과 발사 동작이 작은 크기에서도 읽히는가.
- 모자·머리·옷·장비가 프레임마다 바뀌지 않는가.
- 발과 손 접점이 튀지 않고, 6→1 루프가 이어지는가.
- 동물·수레·배경의 기존 픽셀 아트와 함께 보여도 크기와 색감이 맞는가.
- 장당 원본이 큰 상태에서 메모리·시트 관리·추가 작화 비용이 수용 가능한가.

## 5. 크기·메모리 예상

아래는 **압축 없는 RGBA32 텍스처 데이터만** 계산한 수치다. PNG 파일 용량이나 실제 Unity 메모리 측정값이 아니다. 런타임 압축·패킹·Readable 여부·CPU 복사본·대상 기기에 따라 달라진다.

| 대상 | 계산 | 예상 |
| --- | --- | ---: |
| 1프레임 | 1254×1254×4 bytes | 6,290,064 bytes ≈ **6.00 MiB** |
| 36프레임 | 위 값 ×36 | **215.95 MiB** |
| 36프레임 + 전체 mip 체인 | 위 값 ×약 4/3 | **287.94 MiB** |
| 4096² atlas 4장 | 4096×4096×4×4 | **256 MiB**, mip 없음 |

이 실험의 2D 캐릭터는 mip 없이 검토한다. 프레임 파일은 원본 1254×1254를 유지하며 시트는 태그별로 만든다. 6프레임을 가로 1줄로 붙이면 **7524×1254**이므로, 4096 상한 시트가 필요하면 3열×2행인 **3762×2508** 배치를 사용한다. 4프레임은 2열×2행 **2508×2508**, 2프레임은 2열×1행 **2508×1254**다. 외곽/셀 간 padding을 넣으면 그만큼 시트 크기를 더하고 메타에 기록한다.

1254 원본 제작을 선택하더라도 최종 게임용 export를 1254로 고정해야 하는 것은 아니다. 동일 작화에서 작은 런타임 출력 크기를 시험하고 표시 품질·메모리를 함께 비교할 수 있다. 이 문서에서는 어떤 출력 크기도 최종 승인하지 않는다.

## 6. 파일과 완료 상태

실험 결과는 정식 `Production` 자산과 분리해 한 Try/Test 작업 루트에 모은다. 동작 폴더는 `Clips/HU-01_idle/`, 개별 프레임은 `Frames/idle_01.png`처럼 태그와 1부터 시작하는 프레임 번호를 사용한다. 참고 원본, 투명 프레임, 태그별 시트, 재생 미리보기, 이벤트 메타, 검수 기록을 그 루트의 하위 폴더로 정리한다. 실제 작업 루트와 생성 도구·프롬프트는 해당 작업 README가 정본이다.

작업 루트는 **`ArtSource/Try/Hunter_1254/v001/`**로 지정한다.

```text
Reference/hunter_base_1254.png       # 사용자 첨부 원본 1254×1254, 투명 RGBA
Clips/HU-01_idle/                    # HU-02_walk~HU-08_load도 같은 체계
  Source/                           # 생성 도구의 원본 시트, 원형 보존
  Frames/                           # 정규화한 1254×1254 개별 프레임
  idle.aseprite                     # 편집·duration·태그를 가진 실험 원본
  Export/idle_sheet.png              # 1254 셀 규격 시트
  Export/idle.json                   # 프레임·duration·event 내보내기
Previews/                           # HTML 재생기·384 GIF·동작별 접촉판
Prompts/                            # 도구·프롬프트·참조 파일 기록
QA/                                 # 크기·투명도·정렬·일관성·남은 문제
```

생성 원본 시트와 정규화 결과를 구별한다. 정규화는 셀 추출·투명 캔버스 배치·공통 배율/기준선 정렬 단계이며 작화 변경 내역이 있으면 따로 기록한다. 고해상도 그림에 보이는 도트형 덩어리는 원본 작화의 시각적 특징이다. **1254 이미지가 논리적 32×32 격자의 확대본이라고 표기하지 않는다.**

완료 상태는 `제작 명세 / 작화 시안 / 타이밍 시연 / 애니메이션 검수 / Unity 적용`으로 구별한다. 같은 그림 복사·리사이즈·확대만으로 새로운 작화 프레임을 완료했다고 표시하지 않는다. 36개 파일이 있어도 고유 포즈와 루프 연결이 검수되기 전에는 제작 목록 전체 완료로 기록하지 않는다.
