# 화면/UI P0 · 다음 구현 사이클

Source: [기획서_04 화면/UI](https://app.notion.com/p/4067313398e081b5b0d1fe284d521bc3), v1.2 fetched 2026-10-27. Selected work: UI-001 (existing belt-stage HUD), UI-002, UI-004, UI-006 (prototype window checks), UI-012.

## 이번 범위

- 상단 HUD를 간소화하고 기존 2종 강화를 접이식 패널로 이동. 현재→다음 성능, 비용, 구매 가능/부족/최대 상태와 성공 피드백.
- `(미정)재화` 표기와 HUD 위치로 이동하는 획득 피드백. 보상은 기존 Progress에서 처치 시 한 번만 반영.
- 인터넷 유사 이미지 위에 임시 식별 글자를 표시. Kenney Game Icons CC0 원본/라이선스는 Art/UI/Placeholders에 보관.
- 지도 모달의 실제 Game View와 자동 캡처를 비교하고 캡처 모드/정렬의 복원을 검증.
- 사용자가 지적한 이전 횡스크롤 씬 프리뷰를 벨트스크롤 편집 배치로 교체. Play에서는 편집용 프리뷰를 숨기고 기존 X/Y 이동·Y 정렬·카메라·깊이 사격을 유지.

## 범위 경계

Stage 0~6 저장 ID와 보상/포획 규칙은 유지한다. 새 Stage 01 소탕전/02 구조전 번호 매핑, V 포즈·자동 재사냥, 캐릭터 카드/구출, 다인 자동 이동·사격 AI는 이번 UI 사이클에서 확정하지 않는다. 현재 임시 샷건 성능/골드 저장값은 재사용하되 최종 재화·성장 체계로 확정하지 않는다.

## 검증 계획

기존 벨트스크롤 실행 검사로 기준 상태를 재현하고, UI 전용 검증은 별도 Library 프로필에서 실행한다. 접이식 패널 입력/반복 열기, 실제 버튼 구매·미리보기 일치·부족/최대 상태, 획득 1회 반영, 지도 일시정지/레이어/잠금, 캡처 후 상태 복원을 확인한다. 1280×720, 1024×768, 800×450을 프로토타입 검토 크기로 사용한다. 최종 최소 창 크기와 OS 배율 정책을 확정한 것은 아니다.

수정 전 코드/씬/보고서 및 실제 플레이어 저장 해시는 Docs/Backups/BeforeUI-P0-20261027에 보관했다. 새 결과는 Docs/Validation/UI-P0-*에 기록한다.

## 구현 결과 · 2026-10-27

- 상단 정보 영역을 150→96 기준 픽셀로 줄이고 강화 2종을 접이식 패널로 이동했다. 하단 강화 버튼/U로 열고 닫으며 Escape로 닫는다. 전투는 계속되고 이미 일시정지한 상태도 유지한다. 지도 열기는 강화 패널을 닫고 지도 소유의 일시정지를 적용한다. 포획·결과 단계에서는 강화 패널이 닫힌다.
- `(미정)강화 항목` 패널에서 기존 임시 공격력/발사 간격의 현재→다음 값과 비용, 부족/구매 가능/최대 상태, 구매 성공을 보여준다. 다음 값은 DefenseProgress의 기존 공식과 같은 함수에서 계산한다. 개인/무기 분리 성장이나 새 경제 수식은 추가하지 않았다.
- `(미정)재화`와 회차 획득액, +획득 강조를 표시한다. 기존 월드 코인 비행 대신 최대 12개 UI 아이콘을 재사용해 실제 HUD 아이콘 위치로 보낸다. 시각 효과 종료는 보상을 다시 지급하지 않는다.
- Kenney CC0 이미지 4종에 `재화-01`, `강화-01`, `항목-01`, `항목-02` 텍스트를 Unity UI로 겹쳐 표시했다. 원본 이미지는 수정하지 않았다. 출처·라이선스는 Art/UI/Placeholders/ATTRIBUTION.md에 있다.
- 보스 HP를 상단 HUD 바로 아래로 옮겨 하단 조작부 및 깊이 이동의 발 위치와 분리했다.
- 저장 캡처의 가림은 Canvas를 카메라 모드로 전환하면서 기존 sortingOrder=100이 발 Y 정렬의 월드 캐릭터보다 낮아지는 문제였다. 캡처 동안만 정렬 우선순위를 높이고 모드/카메라/정렬/거리 값을 복원한다. 실제 Overlay Game View에서는 지도 위로 월드 캐릭터가 덮이지 않는 것을 별도로 확인했다.
- 씬에 Belt layout preview를 저장했다. 정지 화면에서 기존 횡스크롤 배치가 보이던 문제를 해결하며, 도로/장애물은 런타임과 같은 BuildRoad 함수를 쓴다. Play에서는 프리뷰를 숨기고 런타임 배우·지형만 사용한다. 원래 캐릭터/배경 참조와 GUID를 보존했다.

## 검증 결과

UI 전용 실행 검증은 U/Escape·반복 열기 6회, 실제 버튼 구매·미리보기·부족/최대 상태, 보상 1회 반영·아이콘 회수, 지도 잠금·레이캐스트·일시정지 복원, 캡처 상태 복원·분리 프로필 재로드를 검사한다. 종료 후 강화 진입 버튼의 비활성 상태와 키보드 재진입 차단도 검사한다. 최초 시도는 버튼과 자식 텍스트의 동일 이름 때문에 테스트 탐색이 모호하여 실패했고, 텍스트 이름을 구분한 후 재실행했다. 최초 보고서도 보존했다. 최종 검사 수/결과는 아래 자동 보고서 기준이다.
