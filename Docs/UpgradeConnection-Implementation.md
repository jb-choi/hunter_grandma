## 시안 해석과 구현

- 하단 강화 버튼 또는 U → 할매 5칸 목록. 첫 칸은 순덕 할매 초상/설명/오른쪽 화살표, 나머지 4칸은 잠긴 실루엣이다. 목록은 마우스 휠/드래그로 스크롤한다.
- 순덕의 화살표 → 같은 창의 오른쪽 영역에 기존 샷건 강화 2종을 표시한다. 목록 보기로 연결 안내에 돌아가며, 닫기/U/Escape/바깥 배경 클릭은 전체 창을 닫는다.
- 시안의 '아직 미정'은 연결 안내와 자리표시자로 유지했다. 순덕에게는 기존 공격력/발사 간격의 현재→다음 값·비용·부족/가능/최대·성공 피드백을 재사용한다. 최종 재화/스탯 명칭·개인/무기 성장 분리·새 해금 규칙은 추가하지 않았다.
- v002의 실제 다섯 명(순덕/화방/기관총/저격/오토바이)을 슬롯에 연결했다. 순덕은 컬러, 잠긴 네 명은 각자의 전용 실루엣이다. 해금 데이터/조건을 새로 만들어 네 명을 활성화한 것은 아니다. 원본/출력물은 읽기 전용으로 사용하며 게임 폴더에 바이트 동일 복사본만 만든다.
- 기존 강화 패널의 전투/일시정지 계약을 유지한다. 창만 열어 전투를 멈추지는 않는다. Space로 쉬기를 제어하고, 지도는 강화창을 닫고 기존 일시정지를 소유한다. 도입·포획·결과에서는 강화 진입이 차단된다. 새 출정에서는 창을 닫는다.

## 검증

`GrandmaUiValidation`에 목록/실루엣 잠금·실제 휠 이벤트·화살표 레이캐스트·상세 진입/복귀·선택 시 재화 불변 검사를 추가했다. 기존 구매·수식/차감·저장·최대 상태·지도/일시정지 검사를 이어서 실행한다. 별도 Library/UI-P0-validation.json만 쓰며 실제 플레이어 저장을 초기화하지 않는다.

`validate-ui`는 실제 Game View 지도 관찰을 요구하는 기존 모드다. 이번 첫 실행은 새 목록/구매/지도 캡처까지 진행했지만 네이티브 Unity 창이 제어 도구에서 사라져 수동 지도 확인 단계에서 시간 초과했다. `Docs/Validation/UI-P0-UpgradeConnection-attempt1.md`에 보존했다. 이 실패를 통과로 기록하지 않는다.

`validate-upgrades` / `Tools/Hunter Grandma/Run Upgrade Connection Validation`은 연결창 자동 UI 검사 모드다. 지도 캡처/레이캐스트/키보드 닫기/일시정지는 검사하되 네이티브 창 직접 관찰은 포함하지 않음을 보고서에 명시한다. 보고서는 `Docs/Validation/UpgradeConnection-validation.md`이다. 실제 새 컴파일/최종 실행 결과는 아래에 기록한다.

최종 기록: 현재 소스의 런타임/Editor 어셈블리를 Unity 번들 Roslyn과 기존 응답 파일로 각각 별도 출력에 컴파일했으며 둘 다 exit code 0·진단 0건이다. Unity 소유의 기존 생성 DLL을 덮지 않았다. 최초 플레이 실행은 80개 검사 후 지도 직접 관찰 대기에서 시간 초과했고, 이후 잔액 즉시 갱신 보정은 컴파일만 확인했다. 전체 실행 PASS로 선언하지 않는다. 네이티브 창 복구와 최종 Editor 재임포트/실행 검증이 남아 있다. 새 자동 모드는 아직 실행하지 않았다.

사용자 지적에 따라 순덕 반복 실루엣을 제거했다. 최신 v002 README/CombatRoles QA의 샷건·화방·기관총·저격·오토바이 역할 원본을 사용한다. `Art/UI/GrandmaPortraits/`에 컬러 5종과 전용 잠금 4종을 복사하고, HUD에 5슬롯 배열 두 개를 저장했다. `GrandmaStageSetup`이 원본과 복사본을 비교해 연결하며 Point 임포트한다. 원본 14개(native 5+컬러 5+잠금 4) 해시가 모두 동일하고, 게임용 PNG 9종은 원본과 바이트가 같다. 기존 폰트 GUID는 값 변경 없이 Unity 직렬화 순서만 바뀌었다.
