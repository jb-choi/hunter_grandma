# Hunter Grandma · 2D 벨트스크롤 전환

기준: [기획서_01 v2.3](https://app.notion.com/p/_01-Desktop-Companion-Stage-v2-4047313398e0818db924d95c5c455419), 2026-10-27 수정본. 원문 스냅샷은 `Docs/Specs/DesktopCompanionStage-v2.3-source.md`에 보관했다.

## 실행과 조작

`Assets/HunterGrandma/Scenes/GrandmaDefense.unity`에서 Play. 기본은 자동 탐색·자동 사격이다.

- WASD / 방향키: 좌우 및 화면 안쪽·바깥쪽 이동. 대각선 이동 속도는 정규화한다.
- Tab: 자동 탐색 ON/OFF. 자동 탐색 중에도 이동키로 개입할 수 있고, 키를 놓은 뒤 1.1초 후 자동 탐색을 재개한다.
- M / 지도 버튼: 지역 선택. Escape로 닫는다.
- Space: 일시정지. R: 현재 사냥 재도전. 지도·일시정지·포획 연출·결과 화면에서는 이동이 차단된다.

수동/자동 비율이 미결정인 기획에 맞춰 기존 방치형 자동 사냥을 유지하면서 직접 이동을 함께 검증할 수 있게 했다. 사격과 포획·귀환은 자동으로 진행한다.

## 추후 구현: 여러 할매의 자동 이동·사격

2026-10-27 사용자 추가 요구사항: 여러 할매가 스스로 이동하면서 총을 쏘는 시스템을 나중에 추가한다. 구체적인 행동 로직은 미정이다. 목표 선택, 이동 방식, 사격 조건, 할매별 역할·협력, 수동 개입 범위는 추후 설계에서 결정한다.

현재 한 명의 할머니가 적에게 접근하고 깊이를 맞춰 사격하는 동작은 벨트스크롤 검증용 임시 로직이다. 이를 최종 자동 행동 규칙으로 확정하지 않는다. 이번 요구사항 기록에서는 다수 할매 AI를 구현하거나 기존 동작을 변경하지 않았다.

## 전투 공간

X는 진행 방향, Y는 발이 놓인 깊이다. 벨트 범위는 Y=-4.0~-0.9, X=-10부터 Stage별 끝 지점까지다. 각 웨이브는 10 유닛씩 앞으로 배치된다. 활성 웨이브의 전진 경계에서 기다렸다가 다음 구역으로 이동한다. 카메라는 X만 추적하며, 배경 타일·뒤쪽 보도·넓은 차도·앞쪽 경계가 깊이를 보여준다.

`BeltSpace`는 이동 경계, 장애물 충돌/우회, 사거리·깊이 판정의 공통 규칙을 담당한다. `BeltStageView`는 배경·길·장애물·카메라·공용 그림자 리소스를 소유한다. 장애물의 바닥 사각형은 이동과 사격을 막는다. 자동 이동은 모서리를 우회하는 경유점을 선택한다.

`BeltActorVisual`은 실제 발 좌표를 유지한 채 자식 스프라이트에 반동·보행·도약·회전을 적용한다. 발 Y가 낮을수록 SortingGroup 순서가 커진다. 할머니·좀비·보스·수레에 공통 그림자를 사용하며, 수레에 적재된 보스는 수레 정렬 그룹에 합친다. 기존 64×64 원본과 보스 이미지 7종을 그대로 사용한다.

## 자동 사냥과 샷건

할머니는 적을 선택해 X 거리를 확보하고 Y 깊이를 맞춘 뒤 사격한다. 좀비는 앞·뒤와 서로 다른 깊이에서 나타나 X/Y로 할머니를 추적한다. 접촉한 좀비는 즉시 사라지는 대신 공격 간격을 두고 피해를 준다.

샷건은 발사 시점의 발 위치와 좌우 방향을 기록한다. 탄환은 목표를 따라 휘지 않고 고정 방향으로 날아가며, 산탄 폭은 거리 d에서 0.10 + 0.06d 유닛이다. 실제 판정은 그 폭에 적 몸체 반경 0.35를 더한 깊이 허용치와 X 사거리·방향·장애물을 함께 검사한다. 탄착 시점에 깊이 밖으로 빠진 적은 맞지 않는다. 상·중·하 산탄 표시와 실제 명중 폭은 같은 함수를 사용한다. 일반 적은 용해·골드, 보스는 제압 상태로 남는다.

보스는 전조 때 할머니의 위치를 기억하고 벨트 안에서 돌진·회전·도약한다. 피해는 장애물로 제한된 실제 발 위치와 할머니의 X/Y 거리가 맞을 때만 발생한다. 깊이를 옮겨 공격을 피할 수 있다. 의사의 회복/소환은 기존처럼 최대 두 번이다.

## 포획과 저장

보스의 제압 지점을 유지하고, 할머니와 수레가 그 X/Y 위치로 접근한다. 적재 후 같은 벨트에서 출발하고 페이드 전환을 거쳐 집 마당으로 돌아온다. 마당 도착 이후에만 신규 포획·CLEAR·다음 Stage 해금을 정산한다.

Stage 0~6, 반복 출정의 신규 개체 ID, 최초 CLEAR 시각, 누적 기록, 실패·후퇴의 골드 보존, 강화·JSON 저장은 유지한다. 저장 스키마는 변경하지 않았으므로 기존 v1 진행 파일을 그대로 읽는다. 임시 이동 좌표와 카메라 위치는 영구 저장하지 않는다.

## 검증

`Tools → Hunter Grandma → Run Belt Scroll Validation` 또는 기존 Stage 검증 메뉴를 실행한다. `Library/BeltScroll-validation.json`을 사용하므로 실제 플레이어 저장 파일과 분리된다. 보고서와 1280×720 / 1024×768 화면은 `Docs/Validation/BeltScroll-*`에 생성된다. 기존 StageV2 검증 자료와 전환 전 코드/씬 백업은 보존했다.

검사 범위: 키 입력 X/Y 이동·양쪽 깊이 경계·전진 경계·카메라·장애물 우회·실제 SortingGroup/그림자·실제 산탄의 다른 깊이 빗맞음·Tab 자동 탐색·보스 전조 깊이 회피·7개 Stage의 제압/실제 위치 적재/귀환·반복 포획·지도·강화·실패/후퇴·저장 재로드.

Unity Editor 6000.3.10f1에서 검증한다. 기존 측면 스프라이트를 좌우 반전하고 절차적으로 움직이는 프로토타입이며, 전용 상하향 걷기 시트나 플레이어 점프 기능은 추가하지 않았다. 새로운 패키지나 project09 변경, ProjectSettings 변경은 없다. 별도 실행파일 패키징과 장시간 성능 측정은 이번 검증 범위 밖이다.

### 최종 검증 결과 · 2026-10-27

Unity Editor 6000.3.10f1에서 **156개 검사 PASS**, 런타임 오류·예외·assertion 0건. 입력 이동/Tab 토글/보스 깊이 회피를 포함한 검사와 7개 Stage 자연 전투·귀환, Stage 0 재사냥, 총 8개 고유 포획 기록을 확인했다. 테스트의 부가 이동/사격 시나리오에서도 자연 획득한 골드만 사용했다. 초기 클리어는 해당 강화 경로에서 약 46~79 시뮬레이션 초였다. 이 수치는 최종 밸런스 확정값이 아니다.

검증 전후 실제 플레이어 저장 파일의 SHA-256이 같았다. 소스 컴파일의 신규 경고는 정리했으며, 손상 저장 복구 테스트가 의도적으로 경고 1건을 발생시킨다. 전투/앞뒤 겹침/스크롤/보스/수레/귀환 화면과 1280×720·1024×768 UI를 시각 확인했다. 씬 차이는 기존 배경에 대한 `beltBackdrop` 참조 한 줄이며, 기존 에셋 GUID는 유지됐다.
