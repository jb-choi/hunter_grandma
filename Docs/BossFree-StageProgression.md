# 보스 없는 웨이브 소탕 · 다음 Stage 자동 이동

2026-10-30 사용자 요청: 모든 스테이지의 보스 등장을 없애고, 스테이지를 끝내면 다음 스테이지로 이동한다. 컴퓨터 사용 기능은 사용하지 않는다.

## 현재 진행 규칙

- 내부 Stage 0~6의 일반 좀비 종류·웨이브 수·기존 순덕 사냥/강화/스킬을 사용한다. Stage 0의 차 마시는 도입과 첫 웨이브 울타리 연출도 유지한다.
- 각 웨이브에서 예정된 좀비를 모두 생성하고 살아 있는 적이 0명이 되면 기존 WaveBreak를 거친다. 중간 웨이브는 기존 전투 구역 이동 조건으로 이어진다.
- 마지막 웨이브 뒤에는 보스 등장/전투/제압/수레 적재/집 마당 귀환을 시작하지 않는다. 일반 좀비 소탕을 CLEAR로 한 번 정산하고 현 사냥 위치에서 멈춘다.
- CLEAR 안내를 1.5 게임 초 표시한 뒤 다음 Stage를 해금·자동 시작한다. 지도/휴식 일시정지 중에는 이동 대기 시간도 멈춘다. 새 Stage의 체력과 전투 집계는 초기화하며 보유 재화·강화·기존 기록은 유지한다.
- 마지막 Stage 6은 `ALL STAGES CLEAR` 결과에서 멈춘다. 존재하지 않는 Stage로 이동하거나 Stage 0으로 자동 순환하지 않는다. 지도 선택 또는 재도전으로 다시 사냥할 수 있다.
- 실패/후퇴에는 CLEAR나 포획을 추가하지 않는다. 도중에 얻은 재화와 과거 기록은 기존처럼 보존한다.

## 구현과 저장 호환

`GrandmaDefense`가 마지막 웨이브 완료에서 `DefenseRun.CompleteWaves` → `DefenseProgress.TryCompleteWaves`로 정산하고 Clear 타이머를 처리한다. `DefenseHud`와 `DefenseMapView`는 일반 좀비 소탕/다음 Stage 자동 이동을 안내한다. 자동 이동 중 결과 패널의 재사냥/지도 버튼은 숨기고, 기존 하단 지도·휴식 조작은 유지한다.

보스 원화, 씬의 기존 직렬화 참조와 BossActor/포획용 코드는 보존했다. 런타임에서는 보스 Spawn을 호출하지 않으며 보스 객체는 비활성 상태다. 사냥 시작에 보스 스프라이트 7종을 필수로 요구하지 않는다. 월드의 보스 등장과 보스 HP UI는 실행 경로에서 나오지 않는다.

저장 JSON의 기존 version 1 필드와 경로를 유지한다. 일반 소탕은 `clearCount`와 최초 CLEAR 시각만 기록하고 `capturedCount`/captives를 추가하지 않는다. 따라서 검증 규칙은 CLEAR 수가 해당 Stage의 과거 포획 수 이상, 포획 수는 실제 저장 개체 수와 일치하는 것으로 분리했다. 옛 포획 기록·개체 ID·최초 시각·재화·강화·스킬 설정은 보존한다. 새 항목 없이 기존 저장을 그대로 읽고 혼합된 기록을 저장/재로드할 수 있다. 구버전 앱은 새 일반 소탕 기록의 완화된 불변식을 알지 못하므로 구버전 실행 파일로 저장을 되돌려 쓰는 호환성은 보장하지 않는다.

## 검증 방법과 상태

`GrandmaStageValidation`의 기존 이동·지도·깊이 판정·장애물·저장 검사를 재사용하고, 자연 진행 검사는 보스 대신 7개 Stage 연속 자동 이동 및 Stage 0 재사냥을 확인하도록 갱신했다. 각 프레임의 보스/포획 단계 부재, 마지막 일반 적 처치, 한 번만 정산, 지도 일시정지 중 CLEAR 대기 정지, 자동 이동의 새 회차/체력 초기화, 최종 Stage 정지, 실패/후퇴·재도전·저장 재로드를 검사한다. 구 포획 모델 검사는 과거 저장 호환 확인용이다.

최초 원본 Editor 실행은 새 런타임/Editor 컴파일 뒤 스크립트 도메인 재로딩 중 시스템 메모리 부족으로 중단됐다. 이 실행의 과거 PASS 보고서는 새 기능 검증으로 집계하지 않는다. 별도 `Library/BossFreeStageBatch` 사본에서 동일 사용 패키지 버전과 동일 코드/씬/게임용 아트로 `Unity -batchmode -nographics -executeMethod HunterGrandma.Editor.GrandmaStageValidation.RunBatch`를 실행했다. 사본의 패키지 명세만 게임에서 쓰는 Sprite/InputSystem/URP/uGUI/TestFramework 및 Unity 기본 모듈·의존성으로 좁혀 임포트 부하를 줄였다. 패키지의 실제 소스는 기존 PackageCache의 동일 버전을 local file 참조로 읽는다. 원본 패키지/설정은 변경하지 않는다. Null graphics에서 화면 캡처는 생략하며 자동 게임 입력/버튼 이벤트·수치/상태를 검사한다. 네이티브 UI 조작과 컴퓨터 사용 도구는 사용하지 않았다.

첫 배치 실행은 49개 검사 후 M 입력에서 실패했다. Game View 포커스가 없는 배치 환경에서 Input System의 기본 Editor 입력 라우팅이 가상 키보드 입력을 전달하지 않았다. `BossFree-batch-attempt1.md`에 원본 결과를 보존했다. 두 번째 실행에서는 검사 중에만 `IgnoreFocus`/`AllDeviceInputAlwaysGoesToGameView`를 적용하고 종료 시 복원했다. 실제 게임의 입력 정책·설정 파일을 바꾸지 않았다.
